    # Analisis Teknis: Flag-Splitting Bypass pada Destructive Command Rule ## Ringkasan Celah Rule yang memeriksa perintah destruktif (misal `rm -rf`, `dd if=...`, `mkfs`, dll.) mencocokkan **combined flag spelling** secara literal. Memisahkan flag menghasilkan efek destruktif yang sama tetapi tidak cocok dengan pattern rule. **Contoh konkret:** ``` rm -rf /path # terdeteksi ✓ rm -r -f /path # LOLOS tanpa deteksi ✗ rm -fr /path # LOLOS tanpa deteksi ✗ (permutasi) ``` --- ## Pola Kerentanan Umum ### Pola rule yang rentan (enumerasi spelling): ```python # BURUK: hanya mencocokkan combined form DESTRUCTIVE_PATTERNS = [ r'\brm\s+-rf\b', r'\brm\s+-fr\b', ] ``` ### Mengapa ini gagal: - `rm -r -f` → tidak cocok dengan `rm -rf` - `rm -f -r` → tidak cocok - `rm --recursive --force` → tidak cocok - Setiap round enumerasi baru membocorkan satu kelas baru (persis seperti lesson 2026-07-24) --- ## Fix yang Direkomendasikan: Negative Continuation Assertion Alih-alih mencocokkan combined spelling, gunakan pendekatan **semantic flag detection** — periksa apakah flag `-r`/`--recursive` DAN `-f`/`--force` keduanya hadir, dalam urutan apapun, sebagai argumen terpisah maupun gabungan. ### Implementasi Python (contoh): ```python import re import shlex def has_flag(args: list[str], short: str, long: str) -> bool: """Cek apakah flag hadir, baik standalone maupun dalam combined short flags.""" for arg in args: if arg == long: return True # combined short flags: -rRf, -rf, -fr, dll. if re.match(r'^-[a-zA-Z]+$', arg) and short.lstrip('-') in arg: return True return False def is_destructive_rm(command: str) -> bool: """ Deteksi `rm` destruktif menggunakan semantic flag parsing, bukan combined-spelling matching. Negative continuation: jika -r DAN -f keduanya hadir → destruktif. """ try: parts = shlex.split(command) except ValueError: return False if not parts or parts[0] not in ('rm', '/bin/rm', '/usr/bin/rm'): return False args = parts[1:] # Pisahkan flags dari non-flags (hentikan di '--' atau argumen non-flag) flags = [] for arg in args: if arg == '--': break if arg.startswith('-'): flags.append(arg) recursive = has_flag(flags, '-r', '--recursive') or has_flag(flags, '-R', '--recursive') force = has_flag(flags, '-f', '--force') return recursive and force ``` ### Verifikasi (runnable): ```python # Test cases — semua harus return True (destruktif terdeteksi) assert is_destructive_rm('rm -rf /path') # combined assert is_destructive_rm('rm -fr /path') # permutasi assert is_destructive_rm('rm -r -f /path') # split assert is_destructive_rm('rm -f -r /path') # split terbalik assert is_destructive_rm('rm -r -f -v /path') # dengan flag lain assert is_destructive_rm('rm --recursive --force /path') # long form assert is_destructive_rm('rm -rRf /path') # -R variant # Test cases — semua harus return False (bukan destruktif) assert not is_destructive_rm('rm -r /path') # hanya recursive assert not is_destructive_rm('rm -f /path') # hanya force assert not is_destructive_rm('ls -rf /path') # bukan rm assert not is_destructive_rm('rm /path') # tanpa flag print("Semua test passed ✓") ``` --- ## Pendekatan Negative Continuation Assertion Sesuai rekomendasi listing (prefer negative continuation assertion), untuk regex-based rule: ```python # Pola: rm diikuti oleh kombinasi argumen yang mengandung -r DAN -f # dalam urutan apapun, dengan argumen lain di antaranya # Negative continuation: "tidak ada cara untuk menyusun rm dengan -r dan -f # yang tidak destruktif, kecuali salah satunya tidak hadir" # Implementasi regex lookahead (untuk rule engine berbasis regex): DESTRUCTIVE_RM_REGEX = re.compile( r'\brm\b' # perintah rm r'(?=(?:\s+(?:-\S+))*\s+-\S*r)' # -r hadir di antara args r'(?=(?:\s+(?:-\S+))*\s+-\S*f)' # -f hadir di antara args # Negative: tidak ada cara untuk rm dengan kedua flag ini yang tidak destruktif ) ``` Catatan: lookahead regex untuk flag arbitrer kompleks; **parser-based approach lebih robust** dan direkomendasikan. --- ##
