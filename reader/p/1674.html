Root Cause Analysis In PR #28, the opaque-exec rule was expanded to catch scripts fed to known interpreters (python, node, bash). However, when an extensionless executable is invoked locally (e.g. `./deploy`, `./build`, `/tmp/task`), static string regex cannot distinguish a compiled ELF/PE/Mach-O native binary from an opaque shebang shell script without reading the file headers. Consequently, bare extensionless shebang scripts ran completely ungated with no gate stop and no receipt. ### 2. Header Magic Byte Inspection Fix In `src/policy/index.js`, we added `isShebangScriptFile(filePath)` to resolve local executable paths and inspect the first 4 bytes: - Shebang scripts (`#!` = `0x23 0x21`): categorized as opaque scripts -> GATED. - Compiled native binaries (ELF `\x7fELF`, Windows PE `MZ`, Mach-O): categorized as compiled binaries -> UNGATED. - Read-only tools (`cat`, `head`, `less`, `grep`) leading the command segment remain exempt. ```javascript function isShebangScriptFile(filePath) { try { const resolved = path.resolve(process.cwd(), filePath); const stat = fs.statSync(resolved); if (!stat.isFile()) return false; const fd = fs.openSync(resolved, "r"); const buf = Buffer.alloc(4); const bytesRead = fs.readSync(fd, buf, 0, 4, 0); fs.closeSync(fd); if (bytesRead < 2) return false; if (buf[0] === 0x23 && buf[1] === 0x21) return true; // #! shebang script if (bytesRead >= 4 && buf[0] === 0x7f && buf[1] === 0x45 && buf[2] === 0x4c && buf[3] === 0x46) return false; // ELF if (buf[0] === 0x4d && buf[1] === 0x5a) return false; // Windows PE if (bytesRead >= 4 && ((buf[0] === 0xfe && buf[1] === 0xed && buf[2] === 0xfa && buf[3] === 0xce) || (buf[0] === 0xcf && buf[1] === 0xfa && buf[2] === 0xed && buf[3] === 0xfe) || (buf[0] === 0xca && buf[1] === 0xfe && buf[2] === 0xba && buf[3] === 0xbe))) return false; // Mach-O for (let i = 0; i < bytesRead; i++) { if (buf[i] === 0) return false; } return true; // text script } catch { return false; } } ``` ### 3. The consequence, without overclaiming: the header is read through `open()`, which does follow a symlink, so classification reads real bytes. But the path handed to `subprocess.run` is the unresolved one, so the check and the execution resolve independently, and a link repointed between them is executed unchecked. `realpath` narrows that window.
