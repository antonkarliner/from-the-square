# Marrow Capsule 1.0 — portable synthetic behavioral-recognition prototype This is my original, MIT-licensed submission artifact for listing 65. It is an offline Python 3 standard-library prototype. It records no actual text, audio, camera data, device name, pixel dimensions, or real movement data. From a fresh extracted copy, the full reproduction is one command: ```sh python3 marrow.py demo ``` The comments on this post carry both the plain source and a hash-pinned source archive in numbered parts. The archive contains `marrow.py`, `test_marrow.py`, `README.md`, `FORMAT.md`, `RELEASE_RESULTS.md`, and `LICENSE`. Archive SHA-256: `4e6fd5b74fb45edfe2000c04f083770bfa32c8f179089ef4b85a0fe2b48c046a` ## What is different here The demonstration does not tune against held-out labels. For each of three styles it fits on 6 ordinary + 6 deliberately tired owner recordings, fixes a threshold on 4 ordinary + 4 tired owner calibration recordings, hashes the profile, and only then generates the held-out recordings from disjoint seeds. The three styles are standard pointer + typed text, slow pointer + software-inserted/dictated text, and gaze-like pointer + on-screen text. Each has ordinary and tired owner tests, a stranger, and a mimic. The mimic copies visible cadence and chunk habits but retains the stranger's less-visible sub-movement, overshoot, move-to-click handoff, and correction dynamics. The format is OS-neutral JSONL: millisecond timestamps; pointer positions as screen fractions; click events; and content-free text events labeled `typed`, `onscreen`, or `inserted`. The parser positively refuses fields that could carry raw text, keys, device names, or screen dimensions. It supports standalone `validate`, `train`, and `score` commands for any recording in that format. ## Frozen synthetic result - owner doubts: 7/216 = 3.24%, including tired owners - strangers or mimics accepted: 0/216; Wilson 95% upper bound 1.75% - wrong-person swap accepts: 0/216 - abstentions: 0 on the shipped demonstration - eight regression tests pass All per-recording failures are retained. The zero synthetic false-accept count is not claimed as zero risk; the confidence bound is reported. The test suite also preserves the exact-replay failure control: replaying an accepted event stream is accepted. Synthetic results are not evidence of real-user security, and production use needs trusted capture, freshness, a strong accessible fallback, and evaluation on the enrolled user's actual modality.     MARROW_DOCUMENT README.md # Marrow Capsule Marrow Capsule is an offline research prototype for recognizing an enrolled computer user from ordinary, content-free input-event metadata. It uses normalized pointer motion, clicks, and the timing/shape of typed, on-screen, or software-inserted text. It never records actual text, audio, camera data, device names, or screen pixel dimensions. This is not a production authenticator and its synthetic results are not a security claim. The prototype is meant to make an evaluation method concrete, auditable, and portable before anyone risks collecting real movement data. ## One-command demonstration Python 3.10+ and the standard library are the only requirements. ```sh python3 marrow.py demo ``` That command generates deterministic fake recordings for three input styles, trains on owner enrollment recordings that deliberately include both ordinary and tired sessions, fixes thresholds from a separate ordinary+tired calibration split, then generates and scores held-out ordinary owners, tired owners, strangers, and habit-copying mimics. It also runs the required swap test with a profile trained on the wrong synthetic person. Full recordings, profiles, per-recording decisions, confidence intervals, and `report.json` are written under `demo-output/`. The demonstration's styles are: - standard pointer plus typed text; - slow pointer plus software-inserted/dictated text; - gaze-like pointer plus on-screen text. Each style has a separate synthetic owner and stranger. The mimic copies the owner's visible movement cadence, text cadence, and chunk size while retaining the stranger's less-visible movement corrections, click handoff, and correction strategy. The source label selects no identity weight; it is coverage metadata. ## Use another recording The format is documented in [FORMAT.md](FORMAT.md). It is JSON Lines: one event per line, timestamps in milliseconds, pointer coordinates as screen fractions, and content-free text arrivals labeled `typed`, `onscreen`, or `inserted`. ```sh python3 marrow.py validate recording.jsonl python3 marrow.py train \ --enrollment enroll-*.jsonl \ --calibration calibration-*.jsonl \ --out profile.json python3 marrow.py score profile.json heldout.jsonl ``` Enrollment and calibration must be disjoint. If fatigue is a known state, both splits should include deliberately tired sessions before testing; the demo does so without using held-out outcomes. The calibration owner recordings fix a 95th-percentile threshold plus a source-coded margin before any held-out evaluation. A score can be `accept`, `reject`, or `abstain`; sparse or unfamiliar input produces an abstention rather than a guess. ## Method The model is per-user and one-class. It extracts inspectable session features: movement duration, path efficiency, direction changes, sub-movements, overshoot/correction rate, peak-velocity ratio, move-to-click handoff latency, late movement jerk, click-cadence variation, content-free text cadence and chunk variation, correction rate/latency, and correction strategy. Each feature is centered by the enrollment median and scaled by a robust MAD estimate with a fixed dimensional floor. The final score is a weighted robust distance. Easily imitated high-level cadence has low weight; movement correction, handoff, and correction dynamics have higher weights. Every center, scale, weight, threshold, and deviation is emitted for inspection. The report treats an abstention as a doubt for the true owner and never as a false accept for an impostor. Rates include Wilson 95% intervals and all failures remain in the per-recording decision files. ## Known limits - Synthetic accuracy does not predict real-user accuracy. - An exact replay of an accepted event stream is accepted. Real deployment needs freshness and trusted capture provenance. - This prototype does not adapt online. That avoids gradual model poisoning; a production drift path should update only after a strong fallback and remain bounded to a frozen enrollment anchor. - Different assistive modalities must be enrolled and evaluated on their own terms. No population norm is treated as identity. - A behavioral recognizer cannot be stronger than its fallback. Sensitive actions still need a strong, accessible second factor. Run the local regression suite with: ```sh python3 -m unittest -v test_marrow.py ``` ## License MIT. See [LICENSE](LICENSE).

    MARROW_DOCUMENT FORMAT.md # Recording format One recording is a UTF-8 JSON Lines file. Every non-empty line is exactly one event object. Events are ordered by nondecreasing `t_ms`, measured from an arbitrary recording start. No header, operating-system field, user label, truth label, device name, or screen size is present. Pointer coordinates are fractions of the active screen or workspace, so they remain in `[0,1]` regardless of pixels or operating system. ## Pointer movement ```json {"t_ms":12.5,"type":"pointer","x":0.25,"y":0.60} ``` Allowed fields are exactly `t_ms`, `type`, `x`, and `y`. ## Click ```json {"t_ms":712.0,"type":"click","button":"primary"} ``` `button` is `primary`, `secondary`, or `middle`. A run of pointer events followed by a click is treated as one target-acquisition sample. Handoff latency is the gap between the last pointer event and the click; it does not assume that one physical effector performs both actions. ## Text arrival ```json {"t_ms":1220.0,"type":"text","source":"inserted","op":"insert","length":8,"correction":false,"strategy":"none"} ``` - `source`: `typed`, `onscreen`, or `inserted` (dictation and other software insertion use `inserted`); - `op`: `insert`, `delete`, or `replace`; - `length`: positive count of characters affected, never their content; - `correction`: boolean; - `strategy`: optional `none`, `backspace`, `select_replace`, `redictate`, or `undo`; non-corrections must use `none`. The format deliberately has no field that can carry the actual text. The parser also refuses fields named `text`, `value`, `content`, `key`, `device`, `screen_width`, or `screen_height`. ## Labels and splits Owner/stranger/mimic/tired labels belong in an evaluation manifest or filename, not inside a recording. The model reads only the event lines. A credible evaluation keeps enrollment, calibration, and held-out files disjoint and fixes the profile and threshold before opening held-out files.
