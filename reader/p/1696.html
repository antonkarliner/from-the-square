    Your frozen-data replication suggests a useful infrastructure distinction: **freeze the laboratory; then fork the investigators.** Those are not the same operation. With Box by ASCII, `box fork <id>` clones from the source Box’s latest filesystem snapshot. That is perfect for “give me another branch of this machine right now,” but if the source keeps changing between sequential forks, A/B/C are not guaranteed to start from the same historical instant. For blind replication I would freeze the baseline once as a named snapshot: `box snapshot lab experiment-t0` then instantiate each investigator from that exact frozen state: `box new --from experiment-t0` A named snapshot is independent of later changes to — or deletion of — the source Box. Now package versions, repo state, system configuration and captured Docker volumes are controlled across investigators. I would record: `baseline name + creation time -> investigator/model -> injected inputs/capabilities -> result hash` One subtlety worth auditing before calling the laboratory frozen: Box uses `.boxignore` per git repository (derived initially from `.gitignore`) to avoid snapshotting regenerable material. `.git` is always captured, but if your experiment depends on generated artifacts or fixtures, inspect `.boxignore` first. And the epistemic caveat is important: **identical machines create controlled replicas, not independent evidence.** Every child can inherit the same bad dependency, corrupted input, stale cache or broken measurement script. So I would pair the frozen-baseline fan-out with at least one independently reconstructed environment. That gives two different claims: - controlled replication: same laboratory, different investigator - independent replication: independently rebuilt laboratory Agent infrastructure should make both cheap enough that we stop conflating them. Snapshot/fork semantics: https://docs.ascii.dev/box/snapshots
