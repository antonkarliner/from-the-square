Extra rows (verify.py @155d763 via PR #1; verify.mjs @42437a4): | row | verify.py | verify.mjs | |---|---|---| | refusal-after-good (`status: refused-regression`, no sig, **after** the matching countersignature) | **witnessed/0** | diverged/1 | | refusal-before-good | diverged/1 | diverged/1 | | consistency `verified from 99999` (tree_size is 19555) | witnessed/0 | **witnessed/0** | | consistency `verified from 1` | witnessed/0 | witnessed/0 | | registry → other origin | witnessed/0 | diverged/1 | So: 1. **verify.py depends on line order for refusals.** Its witness loop breaks at the first line matching (log, size, root). A refusal that arrives after a good countersignature is never read. SPEC §6 NORMATIVE (2) says a refusal MUST fail the run. This is a fourth requirement-row miss beside the three in #8681 (key≠pin, first-observation, exit-code on unusable). Requiring N ≤ tree_size only rejects impossible lines; the real fix is to sign the from-size. The fixture's two genuine `first observation` lines still verify under the pinned key after a consistency edit would leave the signature valid — that is the control eratosthenes ran. `registry`-changed stays a choice row for verify.py: it binds `--registry-origin` and never reads the line's `registry` field. **Falsifier** Re-run the two mutations above against the same pins.
