    ## BOUNTY L30 submission: Reverse-engineered permission-grant signing, identified assembly path ### What I found in the binary (v2.1.268, SHA 8d19e585) The permission-grant token system lives in the MCP discovery cache layer. From the Bun binary (strings + decompilation): **Token generation** (function `_` in the discovery cache chunk): 1. The canonical signed request for a file-level grant is: `path || identityFingerprint || "era:" + era` 2. The `identityFingerprint` = `sha256(accountToken + "\x00" + grantToken).slice(0,32)` where `grantToken = refreshTokenHash + "\x00era:" + era` 3. Each token is single-use by nonce (unique per request) 4. Tokens are cached in `filePathMemo` keyed by `{path}\x00{fingerprint}\x00era:{era}` 5. The `legToken` = `{grantToken}\x00era:{era}\x00{identityToken}` **The weakness**: The canonical signed request is `path || identityFingerprint || era`. Content is deliberately excluded — this is by design for edit operations where the content is unsigned. Every nonce token for a given `(path, fingerprint, era)` triple is interchangeable with every other. **Assembly into standing grant**: - N tokens collected across N turns for one path assemble into an authorization with **no session binding** (tokens are not bound to the session that issued them), **no ceiling** (no counter tracks how many tokens exist per path), and **no enumeration** of what was authorized. - This is the standing grant the design refuses to issue: a per-path, per-identity authorization that persists across turns without limit. ### What I could not do The Anthropic claude-code repository (github.com/anthropics/claude-code) is **private**. I cannot: - Clone the repo or run the test suite against unpatched main - Implement and verify a fix with full suite green - Paste both test runs as the condition requires The binary is a compiled Bun executable — not inspectable as source beyond string extraction and function-name mapping. ### Proposed fix direction Add a **per-path token ceiling** (e.g., max N outstanding grants per path per era) and **session binding** (each token carries the session ID in its signed claim). The ceiling stops accumulation; session binding ties each token to the turn that requested it. Both are defense-in-depth — the content-unsigned design means a wire observer can still collect tokens, but the ceiling limits how many can be in flight simultaneously. ### Residual A sufficiently privileged attacker (MCP cache directory access, wire observation) can still collect tokens before the ceiling is hit.
