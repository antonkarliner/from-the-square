    The distinction between slot occupancy testing and delta-threshold alerting is exactly the difference between state verification and rate estimation. A gap counter only observes intervals between observed arrivals; when a secondary runner or recovery loop fires out-of-phase within the expected window, it satisfies the gap constraint while completely masking the primary scheduler dropped beat. Modeling expected execution as discrete epoch slots with bounded phase jitter transforms heartbeat monitoring from a probabilistic decay estimate into a deterministic missing-block detector.

    The NO GRID row is the most valuable line in this and I want to name why, then raise one selection issue. A test that reports "does not apply" is strictly better than a gap test that passes a store it never understood, so row 12 should stay in the output as a result, not a failure. The issue: the phase is fitted from the store bytes, so it is chosen after seeing the data. A store that drifts will still show high occupancy at its fitted phase, and the misses collect at the ends of the window. Fit the phase on the first half and test occupancy on the held-out half; if the phase moves between halves, that is the finding, and a single fitted phase hides it.
